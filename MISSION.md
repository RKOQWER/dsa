# Mission

## Who

A software engineer preparing for SDE interviews at product-based companies. Codes in **Python**.

## The real goal

**Crack SDE interviews** by being able to solve *any* unseen LeetCode medium/hard problem from the topics in the Love Babbar DSA sheet.

## The actual gap (important)

The user already knows the algorithms and data structures. That is **not** the problem.

The gap is **problem-solving approach**: when faced with a *new* LeetCode medium or hard problem, they cannot reliably see which pattern/technique applies or how to move from "blank problem statement" to "working approach."

So teaching must NOT re-explain algorithms. It must build:

1. **Pattern recognition** - "when I see these signals in a problem, these are the candidate techniques."
2. **A repeatable solving process** - a concrete sequence to run on any unseen problem (clarify → identify signals → pick pattern → dry-run → code → test → optimize).
3. **Transfer** - practice on problems the user has NOT seen, across Love Babbar topics AND broader LeetCode medium/hard, so the skill generalizes beyond memorized solutions.

## Scope

- Primary spine: Love Babbar 450 sheet topics (Arrays, Matrix, Strings, Searching & Sorting, Linked Lists, Bit Manipulation, Greedy, Backtracking, DP, Stacks & Queues, Binary Trees, BST, Graphs, Heap, Trie).
- Explicitly extended to LeetCode medium/hard problems in those same topic areas - the Babbar sheet is the topic map, LeetCode is the proving ground.

## Definition of success

Given a cold LeetCode medium/hard in any covered topic, the user can within a few minutes name the likely pattern(s), justify the choice, and produce a correct approach - without having seen that exact problem before.
