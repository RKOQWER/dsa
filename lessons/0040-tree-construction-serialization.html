Tree construction & serialization — rebuild a tree from its traversal

Traversal flattens a tree into a sequence (Lessons 16, 17, 38). This lesson runs the arrow backwards: given the sequence, reconstruct the tree — and, more generally, encode a tree to a string and decode it back. Two facts do all the work: in any traversal, the position of the root tells you where the left and right halves split; and a traversal that records nulls is self-delimiting, so a single left-to-right pass can rebuild the exact shape. Master these and "construct from preorder and inorder" and "serialize/deserialize" stop being separate tricks and become one idea seen from two sides.

2. From Lesson 17, a level-order (BFS) traversal visits nodes top-to-bottom, left-to-right. Why is it a natural choice for serializing a tree?

Deriving construction from preorder + inorder

Take build a binary tree from its preorder and inorder sequences. Neither sequence alone is enough (many trees share a preorder), but together they pin down one unique tree. The derivation is to ask what each sequence tells you.

Derive it

Preorder gives you the root; inorder gives you the split. Preorder is (node, left, right), so its first value is the root. Inorder is (left, node, right), so once you know the root's value, its position in the inorder sequence separates everything to its left (the entire left subtree) from everything to its right (the entire right subtree). The count of elements on the left tells you how many of the following preorder values belong to the left subtree; the rest belong to the right.

  • Take the next preorder value as the current root.
  • Find it in inorder; the elements before it are the left subtree, the elements after are the right subtree.
  • Recurse: build the left subtree from the matching preorder/inorder slices, then the right. Preorder is consumed strictly left to right, so a single moving index over preorder suffices.
def buildTree(preorder, inorder):
    idx = {v: i for i, v in enumerate(inorder)}   # O(1) root lookups
    self_pre = iter(preorder)
    def build(lo, hi):                            # inorder range [lo, hi)
        if lo >= hi: return None
        val = next(self_pre)                       # next preorder value = this root
        root = TreeNode(val)
        mid = idx[val]                             # its split point in inorder
        root.left  = build(lo, mid)                # left subtree first (preorder order!)
        root.right = build(mid + 1, hi)
        return root
    return build(0, len(inorder))

The insight (= the pattern): one sequence names the roots in the order you need them (preorder for top-down, postorder consumed from the end for the same effect), and a second sequence (inorder) tells you, for each root, how to split the remaining elements into its two subtrees. Construction is just traversal read in reverse: instead of flattening a tree into an order, you let the order dictate the tree.

The two gotchas that flip the template

  • Preorder + postorder is NOT always unique (a node with a single child is ambiguous), so that variant only reconstructs one valid tree and uses a different split rule — a reminder to always check which two orders you are given.
  • Postorder consumed from the end behaves like preorder reversed: if you build from inorder + postorder, read postorder right-to-left and build the right subtree before the left, mirroring the template above.

Serialization: encode so decode is unambiguous

Derive it

Why a plain preorder string fails, and the one fix. If you serialize a tree as its preorder values with no markers, you cannot decode it — "1 2 3" could be many shapes, because you never recorded where the nulls were. The fix is to make the encoding self-delimiting: emit a marker (say #) for every null child. Now preorder is reversible, because the moment you read a # you know that branch ended, so a single left-to-right cursor rebuilds the exact shape.

MARK = '#'
def serialize(root):
    out = []
    def pre(node):
        if not node:
            out.append(MARK); return            # record the null
        out.append(str(node.val))
        pre(node.left); pre(node.right)
    pre(root)
    return ','.join(out)

def deserialize(data):
    vals = iter(data.split(','))
    def build():
        v = next(vals)
        if v == MARK: return None               # a recorded null ends this branch
        node = TreeNode(int(v))
        node.left = build(); node.right = build()
        return node
    return build()

The insight (= the pattern): encode and decode must agree on one order and on recording nulls. Preorder-with-nulls is the compact DFS codec; a level-order (BFS) codec with null markers is the common alternative and the one most interviewers expect to see — same principle, a queue instead of recursion. The deserialize is literally the construction derivation from above with the nulls handed to you explicitly rather than inferred from a second sequence.

When to reach for this pattern, and why it works

Reach for construction when you are handed one or more traversal sequences and asked to produce the tree, and for serialization when you must persist, transmit, or hash a tree and later rebuild it exactly (the classic "design a codec" problem, and the backbone of "find duplicate subtrees" where each subtree's serialization is its identity). It works because a traversal is a lossless linearization as long as structure is recoverable: either a second sequence supplies the left/right split (construction from two orders), or null markers supply it directly (serialization) — and in both cases a single recursive pass that consumes the sequence in its own order rebuilds each node before its children, giving O(n) time with an index map for O(1) root lookups.

The discrimination to make under pressure is which sequences you hold and whether they determine a unique tree. Inorder + (preorder or postorder) is unique; preorder + postorder is not. If you are building from a sorted array into a balanced BST, there is no second sequence at all — you pick the middle as root for balance (a different problem, closer to Lesson 18). Name the inputs first; the template follows from them.

The template

# Construct from preorder + inorder (unique) — O(n) with an index map
def buildTree(preorder, inorder):
    idx = {v: i for i, v in enumerate(inorder)}
    it = iter(preorder)
    def build(lo, hi):
        if lo >= hi: return None
        root = TreeNode(next(it))
        mid = idx[root.val]
        root.left  = build(lo, mid)
        root.right = build(mid + 1, hi)
        return root
    return build(0, len(inorder))

# Serialize / deserialize — preorder with null markers (self-delimiting)
MARK = '#'
def serialize(root):
    out = []
    def pre(n):
        out.append(MARK if not n else str(n.val))
        if n: pre(n.left); pre(n.right)
    pre(root); return ','.join(out)

def deserialize(data):
    vals = iter(data.split(','))
    def build():
        v = next(vals)
        if v == MARK: return None
        n = TreeNode(int(v)); n.left = build(); n.right = build(); return n
    return build()

Composition — how a Hard is built from this pattern

Serialize and Deserialize Binary Tree (Hard 297) — link — composes the self-delimiting preorder encoding (this lesson) with the construction-from-a-single-cursor idea (this lesson) and a traversal choice (Lessons 16/17).

Show the decomposition (try it yourself first)

The ask: design serialize(root) -> str and deserialize(str) -> root that round-trip any binary tree (arbitrary values, arbitrary shape) exactly.

Piece A — a self-delimiting traversal (this lesson): choose preorder and emit a null marker for every missing child. This is the only addition over a plain traversal, and it is what makes decoding unambiguous — the markers record exactly where each branch ends.

Piece B — decode = construction with a single moving cursor (this lesson): read the tokens left to right; a value becomes a node whose left and right are built by recursive calls that consume the next tokens, and a marker returns null. This is identical to construction from preorder + inorder, except the nulls are given to you explicitly instead of inferred from inorder, so you need only one sequence.

The traversal choice (Lessons 16/17): DFS preorder-with-nulls is compact and recursive; an interviewer may ask for the BFS/level-order codec instead — same principle, a queue emitting a marker per missing child, decoded by re-reading the queue order. Either is accepted; know both exist.

The Hard = (preorder + null markers to make the string reversible) + (one-cursor recursive rebuild). Both are this lesson; the only judgment call is which traversal order to encode in. Name the pieces and the Hard stops being hard.

When to use it, and why

Construction: you are handed traversal sequence(s) and must produce the tree. Serialization: you must persist/transmit/hash a tree and rebuild it exactly (codec, duplicate-subtree identity). Works because a traversal is lossless when structure is recoverable — a second sequence supplies the left/right split, or null markers supply it directly — and one recursive pass consuming the sequence in its own order rebuilds each node before its children, O(n).

The two facts

  • Root position gives the split: preorder's first (or postorder's last) value is the root; its index in inorder splits left vs right subtree.
  • Recording nulls makes a single order reversible: preorder-with-null-markers (or BFS-with-markers) is self-delimiting, so one left-to-right cursor rebuilds the shape.

Uniqueness check (do this first)

Inorder + preorder or inorder + postorder = unique. Preorder + postorder = NOT unique. Sorted array into balanced BST = no second sequence, pick the middle.
