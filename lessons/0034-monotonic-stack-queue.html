Monotonic Stack & Queue — the structure that answers "next greater" in one pass

A monotonic stack keeps its elements sorted (increasing or decreasing) by discarding ones that can never again be the answer. It turns a whole class of O(n²) "for each element, scan for the next/previous element bigger/smaller than it" problems into O(n). Once you see why you're allowed to throw elements away, the pattern is unmistakable.

Deriving the monotonic stack

Take Next Greater Element: for each element, find the first element to its right that is strictly greater; if none, report -1.

Derive it

Brute force: for each i, scan right until you find something bigger → O(n²).

Spot the waste by asking who is still "waiting" for an answer. Walk left to right. An element that hasn't yet found a greater element to its right is waiting. Here's the key observation: keep the waiting elements in a stack, and suppose a new element x arrives. Any waiting element smaller than x has just found its answer — it's x. Moreover, once such a smaller element is resolved and removed, it is gone forever and can't block anyone.

The deeper insight — why the stack stays sorted. After resolving everyone smaller than x, the elements still waiting are all ≥ x, and we push x on top. So the stack is always in decreasing order from bottom to top. That ordering is not something we impose; it is a consequence of popping everyone the new element shadows. And "shadows" is the whole point: if x is taller than the elements below it, those elements can never be the next-greater for anything further right, because x stands in front of them — so discarding them loses nothing.

def next_greater(nums):
    n = len(nums)
    ans = [-1] * n
    stack = []                        # holds indices, values decreasing
    for i, x in enumerate(nums):
        while stack and nums[stack[-1]] < x:
            ans[stack.pop()] = x      # x is the next greater for popped index
        stack.append(i)
    return ans

Each index is pushed once and popped at most once → O(n). The stack is the set of still-unanswered elements, kept monotone for free.

The transferable shape: reach for a monotonic stack whenever each element needs the nearest element in some direction that is greater or smaller than it, or when you're computing spans/areas bounded by such elements. Flip the comparison (< vs >) to switch between next-greater and next-smaller; iterate right-to-left to get the previous element instead of the next. The monotonic queue (a deque) is the same idea for a sliding window: it keeps candidates for the window's max/min and evicts from the front when they fall out of the window and from the back when a new element shadows them.

When to reach for it, and why

  • Each element needs the nearest greater/smaller element to its left or right (next greater, previous smaller, stock span, daily temperatures). Because a newly arrived element permanently resolves and removes every waiting element it shadows, each element is touched O(1) amortized times, giving O(n) instead of the O(n²) of scanning for each element.
  • You're measuring an area or span bounded by "the first smaller element on each side" (largest rectangle in a histogram, maximal rectangle). The stack hands you the left and right boundaries of each bar's maximal rectangle exactly when the bar is popped, so you compute all boundaries in one pass.
  • You need the max or min of a sliding window as it moves (sliding window maximum). Use a monotonic deque: it maintains the window's candidates in sorted order, evicting shadowed ones from the back and expired ones from the front, so the window's extreme is always at the front in O(1).

The templates

# Monotonic stack — next greater element (indices, values decreasing)
stack = []
for i, x in enumerate(nums):
    while stack and nums[stack[-1]] < x:
        resolve(stack.pop(), i)      # x at i is the next greater
    stack.append(i)

# Monotonic deque — sliding window maximum, window size k
from collections import deque
def maxSlidingWindow(nums, k):
    dq, out = deque(), []            # dq holds indices, values decreasing
    for i, x in enumerate(nums):
        while dq and nums[dq[-1]] <= x:   # x shadows smaller tail
            dq.pop()
        dq.append(i)
        if dq[0] == i - k:                # front fell out of the window
            dq.popleft()
        if i >= k - 1:
            out.append(nums[dq[0]])       # front is the window max
    return out

Composition — a Hard built from monotonic stack + earlier patterns

Maximal Rectangle (Hard) — link. Composes the monotonic-stack histogram solution with prefix-sum-style row accumulation (Lesson 4) and grid traversal (Lesson 9/29).

Show the decomposition (try it yourself first)

The problem: in a binary matrix, find the largest rectangle containing only 1s.

Pattern A — turn each row into a histogram (prefix accumulation, Lesson 4): for each row, compute heights[c] = number of consecutive 1s ending at this row in column c. A 0 resets the height to 0; a 1 adds one to the height above. Sweeping rows top to bottom builds each histogram in O(cols) — a running accumulation just like prefix sums.

Pattern B — largest rectangle in a histogram (this lesson's monotonic stack): for each row's histogram, run largest-rectangle-in-histogram in O(cols). The monotonic stack finds, for each bar, how far left and right it can extend before hitting a shorter bar — those are exactly the rectangle's boundaries.

The Hard = (accumulate rows into histograms) + (monotonic-stack histogram max) over every row. Total O(rows·cols). The histogram solver is this lesson; the row accumulation is prefix-sum thinking from Lesson 4.

Reference card — Monotonic Stack & Queue

When, and why

Use a monotonic stack when each element needs the nearest greater/smaller element on one side, or you measure spans/areas bounded by such elements. A new element permanently resolves and pops everyone it shadows, so each element is handled O(1) amortized → O(n). Use a monotonic deque for the max/min of a sliding window: it keeps window candidates sorted, evicting shadowed ones from the back and expired ones from the front.

The move

Scan once, maintaining a stack/deque of indices whose values are monotone. On each new element, pop everything it shadows (resolving those elements' answers), then push it. Flip the comparison for greater vs smaller; reverse the scan for previous vs next.

Template

stack = []
for i, x in enumerate(nums):
    while stack and nums[stack[-1]] < x:   # x shadows the top
        resolve(stack.pop(), i)
    stack.append(i)
