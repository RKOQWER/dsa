Stack for Parsing & Design — "the most recent unfinished thing"

Beyond monotonic stacks, the plain stack is the tool whenever a problem has nesting — brackets inside brackets, calls inside calls, operators waiting on operands. A stack holds "the most recently opened thing still waiting to be closed," which is exactly the structure of balanced parentheses, expression evaluation, and several system-design problems like min-stack and LRU cache.

Deriving the parsing stack

Take Valid Parentheses: given a string of ()[]{}, decide if every bracket is correctly matched and nested.

Derive it

What makes nesting hard? A closing bracket must match the most recently opened bracket that is still open — not any earlier one. So as you scan, you need instant access to "the latest unclosed opener," and when it's closed, the next latest becomes current again. That "latest first, and reveal the previous one when removed" behavior is the definition of a stack (LIFO).

  • See an opener → push it; it is now the most recent unclosed context.
  • See a closer → it must match the top of the stack. If it does, pop (that context is finished, revealing the previous one). If it doesn't, the string is invalid.
  • At the end, a valid string leaves the stack empty — nothing unclosed.
def isValid(s):
    pairs = {')':'(', ']':'[', '}':'{'}
    stack = []
    for ch in s:
        if ch in '([{':
            stack.append(ch)
        else:
            if not stack or stack.pop() != pairs[ch]:
                return False
    return not stack

You didn't memorize "use a stack for brackets." You observed that matching needs the most recent unclosed thing, and LIFO is the one structure that gives it. That reasoning generalizes to every nesting problem.

The transferable shape: reach for a stack whenever the problem has nested or deferred structure — things that open and must later close in reverse order, or computations that must wait for their operands. Expression evaluation pushes operands and applies an operator when its inputs are ready. Decoding nested strings (3[a2[c]]) pushes the outer context when a new bracket opens and restores it when the bracket closes. For design problems, the move is to pick the data structures whose operations match the required complexity: min-stack pairs each value with the running minimum so getMin is O(1); LRU cache combines a hashmap (O(1) lookup, Lesson 5) with a doubly linked list (O(1) reordering, Lesson 8).

When to reach for a stack (or a designed structure), and why

  • The input has nesting or must be closed in reverse order of opening (brackets, tags, nested encodings). A closer always refers to the most recently opened context, and LIFO is precisely the structure that keeps the most recent item accessible and reveals the previous one on removal — so a single scan validates or builds the structure in O(n).
  • A computation must wait for parts that come later (operator waiting for operands, deferred evaluation). The stack holds the deferred items until their dependencies arrive, then resolves them top-down — the natural order for nested expressions.
  • A design problem demands specific O(1) operations (min-stack's getMin, LRU's get/put). You don't derive a clever trick; you compose structures whose individual guarantees meet the spec — augment a stack with a running aggregate, or pair a hashmap with a linked list. The skill is reading the required complexities and choosing structures that already provide them.

The templates

# Min-stack: store (value, running_min) so getMin is O(1)
class MinStack:
    def __init__(self): self.st = []
    def push(self, x):
        m = x if not self.st else min(x, self.st[-1][1])
        self.st.append((x, m))
    def pop(self): self.st.pop()
    def top(self): return self.st[-1][0]
    def getMin(self): return self.st[-1][1]

# LRU cache: hashmap (key -> node) + doubly linked list (recency order)
from collections import OrderedDict
class LRUCache:
    def __init__(self, cap):
        self.cap = cap
        self.d = OrderedDict()           # front = least recent
    def get(self, key):
        if key not in self.d: return -1
        self.d.move_to_end(key)          # mark most recent
        return self.d[key]
    def put(self, key, val):
        if key in self.d: self.d.move_to_end(key)
        self.d[key] = val
        if len(self.d) > self.cap:
            self.d.popitem(last=False)   # evict least recent

Composition — a Hard built from a parsing stack + earlier patterns

Basic Calculator (Hard) — link. Composes a parsing stack with careful sign/state handling and the nesting idea applied to parentheses that flip signs.

Show the decomposition (try it yourself first)

The problem: evaluate an expression with +, -, non-negative integers, and parentheses (which can nest and carry a leading sign).

Pattern A — parsing stack for nesting: a parenthesis opens a new evaluation context whose running result and current sign must be remembered and restored when the matching ) closes. Push the current (result, sign) when you hit (, reset to a fresh context, and on ) fold the inner result back into the saved outer one. This is exactly "remember the most recent unclosed context" from this lesson.

Pattern B — running accumulation of signed terms: between parentheses, keep a running result and a sign (+1 or -1) that applies to the next number — a tiny state machine. Multi-digit numbers are accumulated digit by digit, like a scan.

The Hard = (parsing stack to save/restore contexts across parentheses) + (a sign+result accumulator between brackets). The stack mechanics are this lesson; the only subtlety is remembering to push both the result and the sign when a parenthesis opens.

Reference card — Stack for Parsing & Design

When, and why

Use a plain stack when the input nests or must close in reverse order of opening, or when a computation must wait for later operands — LIFO keeps the most recent unclosed context accessible and reveals the previous one on pop, so one scan handles arbitrary nesting in O(n). For design problems, compose structures whose individual operations meet the required complexities (augmented stack for min; hashmap + doubly linked list for LRU).

The move

Push when a context opens or an operand/deferred item appears; pop to match a closer or to apply an operator whose inputs are ready; a valid nesting ends with an empty stack. For design, read the spec's required O(1)/O(log n) operations and pick structures that already provide them.

Template

stack = []
for token in input:
    if opens(token): stack.append(context(token))
    elif closes(token): fold(stack.pop(), token)   # must match
    else: handle(token)   # operand / digit / etc.
