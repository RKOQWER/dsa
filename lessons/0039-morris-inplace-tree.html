Morris traversal — O(1)-space inorder by borrowing null pointers

The iterative traversal of Lesson 38 removed recursion but still paid O(h) memory for its stack. Morris traversal removes that too: it walks a binary tree in inorder using O(1) extra space, by temporarily rewiring the unused null right-pointers of leaves into "threads" that point back to the next node to visit — then undoing each thread as it is used. The same borrow-and-restore discipline powers a small family of "O(1)-space tree" follow-ups: flattening a tree to a list, and populating next-right pointers level by level. This is almost always asked as a follow-up — "now do it without the stack" — so recognize it as the final squeeze on space, not a first resort.

Deriving Morris traversal from the stack's job

Take inorder traversal in O(1) space. Ask precisely what the stack was for: after finishing a node's left subtree, you need a way back to the node so you can visit it and turn right. The stack stored that return address. Morris's idea: store the return address in the tree itself, using a pointer that is otherwise null.

Derive it

The observation: when a node has a left child, the last node its left subtree visits in inorder is that subtree's rightmost node — the inorder predecessor — and that rightmost node's right pointer is null (that is what makes it rightmost). That null pointer is free real estate: thread it to point back at the current node, and when the left subtree's traversal falls off its rightmost end, it lands exactly where it needs to be.

The algorithm, standing at cur:

  • If cur has no left child, visit cur and move right (nothing to the left to do first).
  • If cur has a left child, find its inorder predecessor (go left once, then right until the right pointer is null or loops back to cur). Then:
    • If the predecessor's right is null, this is the first time down: create the thread (pred.right = cur) and move left — you will come back here later.
    • If the predecessor's right already points to cur, you have returned via the thread: remove the thread (pred.right = None) to restore the tree, visit cur, and move right.
def morris_inorder(root):
    out, cur = [], root
    while cur:
        if not cur.left:
            out.append(cur.val)        # visit
            cur = cur.right
        else:
            pred = cur.left            # find inorder predecessor
            while pred.right and pred.right is not cur:
                pred = pred.right
            if pred.right is None:
                pred.right = cur        # THREAD created: remember the way back
                cur = cur.left
            else:
                pred.right = None       # THREAD removed: tree restored
                out.append(cur.val)     # visit on the way back up
                cur = cur.right
    return out

The insight (= the pattern): the stack's return address becomes a temporary edge inside the tree. Each left-having node is reached twice — once going down (thread created, go left) and once coming back (thread removed, visit, go right) — so the tree is left exactly as it started, and the extra space is a single pred pointer: O(1). Each edge is walked at most a constant number of times, so the total time is still O(n).

The transferable shape: Morris is one instance of a broader move — when you need to remember a position in a tree but cannot afford a stack, reuse pointers the tree is not currently using to encode that memory, then restore them. Flattening a tree to a linked list and populating next-right pointers are the same discipline: relink existing pointers in place, in O(1) space, using structure the tree already provides.

The sibling tricks: in-place relinking in O(1) space

  • Flatten Binary Tree to Linked List. You want the tree rewired into a right-leaning "list" in preorder. The O(1) trick is pure Morris-flavored relinking: for each node that has a left child, find that left subtree's rightmost node, splice the node's current right subtree onto it, then move the left subtree to the right and null the left. Walk right and repeat. No stack, no recursion — you reuse the rightmost-of-left-subtree idea exactly as Morris does.
  • Populate Next Right Pointers (perfect tree, then any tree). You want each node's next to point to the node on its right at the same level. The O(1) trick uses the next pointers you have already established on the current level to walk across it like a linked list, wiring up the children on the level below as you go — so the previous level becomes the "stack" that threads you across the next. Same principle: the structure you have built so far encodes the traversal state, costing no extra memory.

When to reach for Morris, and why it works

Reach for Morris specifically when a traversal problem imposes an O(1) extra-space requirement — most often phrased as a follow-up after you have given the recursive or stack answer ("can you do it without recursion and without a stack?"). The canonical targets are inorder traversal, validating a BST, kth-smallest, and recovering a BST, all under constant space. It works because a binary tree is full of null pointers that carry no information, and the one piece of state a stack-free traversal needs — "how do I get back up after finishing a subtree?" — can be stored in exactly those null slots and then wiped clean, so the tree is unchanged when you finish and you never allocate memory that grows with the input.

Do not open with Morris. It is finicky — the predecessor search, the create-vs-remove branch, and restoring every thread are all easy to get subtly wrong, and a buggy Morris corrupts the input tree. Give the clean recursive (Lesson 16) or stack (Lesson 38) solution first, state its space cost, and reach for Morris only when the O(1) constraint genuinely demands it. Also note Morris temporarily mutates the tree during the walk, which rules it out if the tree may be read concurrently.

The template

# Morris inorder (above) — the core skeleton you adapt
def morris(root, visit):
    cur = root
    while cur:
        if not cur.left:
            visit(cur); cur = cur.right
        else:
            pred = cur.left
            while pred.right and pred.right is not cur:
                pred = pred.right
            if pred.right is None:
                pred.right = cur; cur = cur.left        # go down, leave a thread
            else:
                pred.right = None; visit(cur); cur = cur.right   # came back: untie, visit, go right

# Flatten Binary Tree to Linked List — O(1) space, in-place relink (Morris-flavored)
def flatten(root):
    cur = root
    while cur:
        if cur.left:
            pred = cur.left
            while pred.right:               # rightmost node of the left subtree
                pred = pred.right
            pred.right = cur.right           # splice current right subtree onto it
            cur.right = cur.left             # move left subtree to the right
            cur.left = None
        cur = cur.right

# Populate Next Right Pointers II — O(1) space, walk each level via the next links you built
def connect(root):
    cur = root
    while cur:
        dummy = Node(0)                      # head of the next level being built
        tail = dummy
        while cur:                           # walk the current level like a linked list
            if cur.left:  tail.next = cur.left;  tail = tail.next
            if cur.right: tail.next = cur.right; tail = tail.next
            cur = cur.next
        cur = dummy.next                     # drop to the level we just linked

Composition — how a Hard is built from this pattern

Recover Binary Search Tree in O(1) space (Medium 99, hard under the space constraint) — link — composes Morris inorder (this lesson) with the "two swapped elements break sortedness" detection you already derived in the BST lesson's composition (Lesson 18).

Show the decomposition (try it yourself first)

The ask: exactly two nodes of a valid BST were swapped; restore it without changing structure, using O(1) extra space. You solved the O(h)-space version in Lesson 18 with a recursive inorder carrying prev; the follow-up removes even that stack.

Piece A — detect the two offenders in a sorted stream (Lesson 18): inorder of a valid BST is strictly increasing; two swapped values create either one descending adjacent pair (if adjacent) or two (if not). The first offender is the larger of the first descent; the second offender is the smaller of the last descent. Capture them in two side variables first and second, comparing each visited value to the previous one.

Piece B — supply the inorder stream with O(1) space (this lesson): replace the recursive/stack inorder with a Morris inorder. At each "visit" step, run the same prev comparison and update first/second. Because Morris restores every thread, the tree is intact when you finish detecting, and you simply swap the two offenders' values at the end.

def recoverTree(root):
    first = second = prev = None
    cur = root
    while cur:
        if not cur.left:
            if prev and prev.val > cur.val:      # a descent (Lesson 18 logic)
                if not first: first = prev
                second = cur
            prev = cur; cur = cur.right
        else:
            pred = cur.left
            while pred.right and pred.right is not cur:
                pred = pred.right
            if pred.right is None:
                pred.right = cur; cur = cur.left
            else:
                pred.right = None
                if prev and prev.val > cur.val:
                    if not first: first = prev
                    second = cur
                prev = cur; cur = cur.right
    first.val, second.val = second.val, first.val

The Hard = (detect two break points in a sorted stream) + (Morris inorder to produce that stream in O(1) space). Both pieces you already own — the detection is pure Lesson 18, and only the Morris plumbing is new. Name the pieces and the Hard stops being hard.

When to use it, and why

Use Morris when a traversal must run in O(1) extra space — almost always a follow-up after the recursive/stack answer. It works because a tree's null right-pointers are free storage for the one fact a stack-free walk needs (the way back up after a subtree), and threading then un-threading them leaves the tree unchanged. Finicky and mutating during the walk, so never open with it; give the clean answer first.

The core move

For a node with a left child, thread its inorder predecessor (rightmost of the left subtree) back to it. First visit down: create the thread, go left. Second visit (thread already points back): remove the thread, visit, go right. No left child: visit, go right. O(1) space, O(n) time, tree restored.

The sibling tricks (same discipline)

  • Flatten to linked list: splice each node's right subtree onto the rightmost node of its left subtree; move left subtree to the right.
  • Next right pointers: use the next-links already built on a level to walk across it and wire the level below — the built structure is the traversal state.

Template (inorder core)

cur = root
while cur:
    if not cur.left: visit(cur); cur = cur.right
    else:
        pred = cur.left
        while pred.right and pred.right is not cur: pred = pred.right
        if pred.right is None: pred.right = cur; cur = cur.left
        else: pred.right = None; visit(cur); cur = cur.right

Watch out

Infinite loop if the predecessor condition drops the is not cur check; corrupted tree if you forget to remove a thread. Morris mutates the tree mid-walk, so it is unsafe for a tree being read concurrently.
