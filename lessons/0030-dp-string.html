String DP — two pointers into two strings as the state

When a problem compares or transforms one string against another (or against itself), the DP state is almost always a pair of indices — one into each string — representing "the subproblem on the two suffixes (or prefixes) from here on." LCS, edit distance, palindromic subsequence, and wildcard/regex matching are all this shape. The hard part is never the recurrence; it's seeing that a string problem is really a walk over a 2D index grid.

Deriving string DP via LCS

Longest Common Subsequence: given strings a and b, find the length of the longest subsequence present in both (characters in order, not necessarily contiguous).

Derive it

Find the choice by looking at the first character of each remaining suffix. Stand at a[i] and b[j]. Compare them:

  • If a[i] == b[j], this character can safely be part of the common subsequence. Take it (+1) and advance both: 1 + dp(i+1, j+1).
  • If they differ, at least one of them is not in the LCS. You don't know which, so try both and keep the better: max(dp(i+1, j), dp(i, j+1)).

The state is the pair of positions (i, j), because your progress through both strings determines the subproblem.

dp(i, j) = 1 + dp(i+1, j+1)            if a[i] == b[j]
         = max(dp(i+1, j), dp(i, j+1)) otherwise

Spot the overlap: many different alignment paths reach the same (i, j), so caching the pair collapses the exponential branching to an O(|a|·|b|) table — the same 2D grid as Lesson 29, now indexed by two strings.

The transferable shape: every two-string DP compares the current characters and branches on match-vs-mismatch, advancing one or both pointers. Edit distance is LCS with three mismatch branches (insert, delete, replace) instead of two. A palindrome problem is this template with the string compared against its own reverse, or with the two pointers moving inward from both ends of one string.

When to reach for string DP, and why

  • The problem aligns, matches, or transforms one sequence against another (or a string against itself), and asks for a best length, a minimum number of edits, or a yes/no match. Because the decision at each step depends only on the current pair of positions and the choices advance those positions monotonically, the subproblems form a 2D grid you can fill once — turning the exponential number of alignments into O(n·m) work.
  • Characters are compared, and on a mismatch there are a small fixed set of moves (skip in a, skip in b, or edit). That small branching factor is what makes the table cheap; if a mismatch allowed arbitrary jumps, it would not be this pattern.
  • For self-palindrome problems, the two pointers index the same string from both ends. The state is still a pair (i, j) meaning "the substring from i to j," and you shrink inward — the same grid, read as a triangle.

The template

# LCS length, top-down
from functools import cache
def lcs(a, b):
    @cache
    def dp(i, j):
        if i == len(a) or j == len(b): return 0
        if a[i] == b[j]:
            return 1 + dp(i+1, j+1)
        return max(dp(i+1, j), dp(i, j+1))
    return dp(0, 0)

# Edit distance — same shape, three mismatch moves
def editDistance(a, b):
    @cache
    def dp(i, j):
        if i == len(a): return len(b) - j   # insert the rest
        if j == len(b): return len(a) - i   # delete the rest
        if a[i] == b[j]:
            return dp(i+1, j+1)
        return 1 + min(dp(i+1, j),     # delete a[i]
                       dp(i, j+1),     # insert b[j]
                       dp(i+1, j+1))   # replace
    return dp(0, 0)

Composition — a Hard built from string DP + earlier patterns

Regular Expression Matching (Hard) — link. Composes the two-pointer string-DP grid with careful case analysis on the pattern, and the feasibility-combine (or) idea from DP recognition (Lesson 26).

Show the decomposition (try it yourself first)

The problem: match string s against pattern p where . matches any single char and * means "zero or more of the preceding element." Return whether the whole string matches.

Pattern A — two-pointer string DP: state dp(i, j) = does s[i:] match p[j:]? Same (i, j) grid as LCS/edit distance.

Pattern B — mismatch case analysis, combined with or (Lesson 26): the branching is richer but still finite. First decide if the current chars match (s[i] == p[j] or p[j] == '.'). Then look at whether p[j+1] is a *:

  • If the next pattern char is *: either use zero copies (skip p[j:j+2] → dp(i, j+2)) or, if the current char matches, consume one char of s and stay on the same star (dp(i+1, j)). Combine the two with or.
  • Otherwise: require a current match and advance both (dp(i+1, j+1)).

The Hard = (string-DP (i,j) grid) + (finite case analysis on the pattern) + (or-combine for "any branch works"). The grid and the combine you already own; the only new thing is enumerating the star's two behaviors cleanly.

Reference card — String DP

When, and why

Use it when you align, match, or transform one sequence against another (or a string against itself) and want a best length, a minimum edit count, or a yes/no match. The decision at each step depends only on the current pair of positions and advances them monotonically, so the subproblems form a 2D (i, j) grid fillable once in O(n·m) — collapsing exponentially many alignments.

The move

State is a pair of indices. Compare a[i] and b[j]: on a match, advance both (and +1 or free, per the question); on a mismatch, branch over the small set of moves (skip a, skip b, edit) and combine with max/min, +, or or. For palindromes, index one string from both ends.

Template

@cache
def dp(i, j):
    if done(i, j): return base
    if a[i] == b[j]: return match_value + dp(i+1, j+1)
    return combine(dp(i+1, j), dp(i, j+1))   # + maybe dp(i+1, j+1) for replace
