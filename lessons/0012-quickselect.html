Quickselect — finding the k-th element without sorting everything

"Find the k-th largest" screams sort it (O(n log n)) or heap (O(n log k)). Both do more work than the question needs. Quickselect answers it in O(n) average by refusing to order the parts of the array that can't contain the answer. By the end you'll derive it from the realization that sorting is overkill.

Deriving quickselect from "sorting is overkill"

Find the k-th smallest element. Brute force: sort the whole array, return index k-1. O(n log n). Where's the waste? Sorting painstakingly orders all n elements, but you only care about one position. Every comparison that orders elements far from rank k is wasted effort.

Recall the one piece of quicksort that does real work: the partition. Pick a pivot, rearrange so everything smaller sits left of it and everything larger sits right. After partitioning, the pivot lands in its final sorted position — say index p — even though neither side is sorted yet.

Derive it

After one partition, the pivot is at its true sorted index p. Now compare p to your target k-1:

  • p == k-1 → the pivot is the k-th element. Done.
  • p > k-1 → the answer is somewhere to the left; the entire right side is irrelevant. Recurse left only.
  • p < k-1 → recurse right only.

Quicksort recurses into both sides (that's why it's O(n log n)). But for a single rank you only ever need one side — the other provably can't hold rank k. Throwing away a side each step gives the geometric series n + n/2 + n/4 + … = O(n) average. That "recurse into one side only" IS quickselect. It's quicksort with the useless half deleted.

import random
def quickselect(a, k):          # returns the k-th SMALLEST (1-indexed)
    target = k - 1              # 0-indexed rank we want in sorted order
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        p = partition(a, lo, hi)
        if p == target:
            return a[p]
        elif p < target:
            lo = p + 1          # answer is to the right; drop the left side
        else:
            hi = p - 1          # answer is to the left; drop the right side

def partition(a, lo, hi):
    # random pivot avoids O(n^2) on sorted/adversarial input
    r = random.randint(lo, hi)
    a[r], a[hi] = a[hi], a[r]
    pivot = a[hi]
    i = lo                      # i = boundary: a[lo..i-1] are < pivot
    for j in range(lo, hi):
        if a[j] < pivot:
            a[i], a[j] = a[j], a[i]
            i += 1
    a[i], a[hi] = a[hi], a[i]   # place pivot at its final index i
    return i

Written as a loop rather than recursion, so there's no extra stack — the "recurse one side" becomes "move one boundary." Same idea.

Why random pivots matter

If you always pick the last element as pivot and the array is already sorted, every partition peels off just one element — n + (n−1) + … = O(n²). Choosing the pivot randomly makes that worst case astronomically unlikely, which is why the average is O(n) and quickselect is trusted in practice. This is the same reason randomized quicksort is the default sort in many libraries.

When to reach for quickselect, and when not to

You want quickselect whenever the problem asks for the k-th largest/smallest value, or the top/bottom k elements, of a static array you're allowed to rearrange, and you only need the answer once. It beats a heap (O(n log k)) and a full sort (O(n log n)) because it does O(n) expected work and never orders the parts that don't matter. You should not use it when the data arrives as a stream and you can't hold or reshuffle it all (a heap is right there), when you need the k elements in sorted order rather than just identified (quickselect leaves each side unsorted), or when a guaranteed worst case matters more than average speed (its worst case is O(n²); a heap's O(n log k) is guaranteed).

Trap — sharpen your discrimination

Kth Largest Element in a Stream (Easy) sounds like quickselect — "k-th largest" — but the data streams in and you must answer repeatedly as new values arrive. Quickselect needs the whole array present and reshuffles it; it can't maintain an answer across insertions. The right tool is a size-k min-heap. Lesson: the "k-th largest" keyword alone doesn't pick quickselect — the static, all-present, one-shot precondition does. On a stream, go heap.

Composition — how a harder problem is built from this pattern

Wiggle Sort II (Medium, but famously hard) — link — composes quickselect (this lesson) with the Dutch-national-flag three-way partition from the same-direction two-pointer idea (Lesson 2 / Lesson 7 territory).

Show the decomposition (try it yourself first)

Rearrange so nums[0] < nums[1] > nums[2] < nums[3] …. It decomposes into two pieces you own:

Piece 1 — quickselect to find the median: the wiggle is only possible if you split the values around the median. Quickselect finds the median value in O(n) without sorting — exactly this lesson.

Piece 2 — three-way partition around the median (Dutch national flag): using the same-direction pointer idea, partition into "greater than median", "equal", "less than median" in one pass. Then place the larger half and smaller half into interleaved index positions (odd indices from the top down, even indices from the bottom down) so equal values never sit adjacent.

The result = (quickselect to locate the median) + (three-way partition to arrange around it). Both are things you've derived. The scary problem is two familiar pieces in a trench coat.

Reference card — Quickselect

The compressed version. Re-reading this should reload the whole pattern.

When to use it, and why

  • k-th largest/smallest or top/bottom k of a static, rearrangeable array, answered once. Partition puts a pivot at its final sorted index; you then recurse into only the side that can contain rank k, discarding the other. That one-sided recursion gives O(n) average, beating both a full sort (O(n log n)) and a heap (O(n log k)).

The one-line reason it works

After a partition the pivot sits at its true sorted position, so comparing that position to k tells you which single side holds the answer — throwing away the other side each step gives the geometric n + n/2 + … = O(n) average.

How to derive it cold

Notice that sorting orders all n elements when you only need one position. Keep just quicksort's partition, and after each partition recurse into the one side that could contain rank k. That's quicksort with the useless half deleted.

Discrimination test (when it does NOT apply)

Streaming data you can't hold or reshuffle → use a size-k heap. Need the k elements in sorted order → quickselect leaves sides unsorted. Guaranteed worst case required → quickselect is O(n²) worst; a heap is a guaranteed O(n log k). Always use a random pivot, or sorted/adversarial input degrades it to O(n²).

Template (Python)

import random
def quickselect(a, k):              # k-th smallest, 1-indexed
    target, lo, hi = k - 1, 0, len(a) - 1
    while lo <= hi:
        p = partition(a, lo, hi)    # pivot lands at final index p
        if p == target: return a[p]
        elif p < target: lo = p + 1 # drop left side
        else:            hi = p - 1 # drop right side

def partition(a, lo, hi):
    r = random.randint(lo, hi); a[r], a[hi] = a[hi], a[r]
    pivot, i = a[hi], lo
    for j in range(lo, hi):
        if a[j] < pivot:
            a[i], a[j] = a[j], a[i]; i += 1
    a[i], a[hi] = a[hi], a[i]
    return i

Complexity and classic problems

Time O(n) average, O(n²) worst; space O(1) with the loop form. Practice set: Kth Largest Element in an Array (M), K Closest Points to Origin (M), Top K Frequent Elements (M), Wiggle Sort II (M).
