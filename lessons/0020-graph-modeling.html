Graph Modeling — the hard part is seeing the graph, not traversing it

Most people can run BFS and DFS in their sleep. Where they freeze is one step earlier: a problem says nothing about "graphs," yet the right move is to build one. This lesson is about that recognition — turning grids, states, strings, and dependencies into nodes and edges so the traversal patterns you already know can take over. By the end you'll have a checklist for spotting a hidden graph and a template for building the adjacency.

Deriving the model: "this problem IS a graph" from first principles

A graph is nothing more than a set of states (nodes) and the allowed moves between them (edges). That definition is the whole trick: almost any problem about "reaching," "connecting," "ordering," or "transforming step by step" is secretly a graph, because each of those words hides a notion of state + transition.

Derive it

Take a word-transformation puzzle: start from "hit", change one letter at a time (each intermediate must be a real word), reach "cog" in the fewest steps.

Brute force: try every sequence of single-letter edits and keep the shortest that reaches the target. That is an explosion of sequences — exponential, and you re-explore the same words over and over.

Spot the waste: the only thing that matters at any moment is which word you are currently on — not how you got there. Two different edit sequences that both arrive at "hot" have identical futures. Brute force re-derives that future every time.

The insight (= the model): make each word a node, and connect two words with an edge when they differ by exactly one letter. Now "fewest edits from hit to cog" is literally "shortest path from node hit to node cog." The exponential sequence-search collapses into a graph with one node per word, and a traversal visits each word once. Recognizing the state (the word) and the move (one-letter change) IS the modeling step — everything after it is a traversal you already know.

The deeper principle (so it transfers)

The modeling question is always the same two-parter: "What is the state, and what are the legal moves from a state?" Answer those and you have your nodes and edges. If the state is a cell, moves are the four neighbours. If the state is a string, moves are single edits. If the state is "courses you have finished," moves are "take a course whose prerequisites are done." Once you can name the state and the move, the problem has already become a graph — and whether you then reach for BFS, DFS, topological sort, or shortest path is a separate, later decision driven by what the question asks.

How to recognise a hidden graph, and how to build it

These are the recurring disguises. Each is written out fully so you can judge whether it fits, not memorize a keyword.

A grid is a graph

When the input is a 2D grid and the problem talks about moving between adjacent cells, treat each cell (r, c) as a node and connect it to its up/down/left/right neighbours (sometimes the 8 diagonals too). You usually do not build an explicit adjacency list for a grid — you compute neighbours on the fly with the four direction offsets, because the grid already encodes the structure.

A set of states with legal transitions is a graph

When the problem is "get from a starting configuration to a goal configuration by applying allowed operations" — word edits, lock combinations, board positions, jumps — each configuration is a node and each legal operation is an edge. You rarely materialise all nodes up front; you generate a node's neighbours lazily when you reach it, because the full state space is often huge.

Dependencies and "must come before" relationships are a directed graph

When items have prerequisites or an order constraint ("you must finish A before B"), draw a directed edge A → B. The problem is then about ordering or reachability in that directed graph. This is the shape that leads to topological sort, which you will meet next lesson.

Pairwise relationships / "are these two connected" is a graph

When you are told pairs that are related (friends, equivalent accounts, merged islands) and asked how many groups exist or whether two things are linked, the pairs are edges and the items are nodes, and the question is about connected components.

How you store it (adjacency)

For an explicit graph given as edges, the default representation is an adjacency list: a dictionary mapping each node to the list of its neighbours. It uses O(V + E) space and lets you iterate a node's neighbours directly, which is what every traversal needs. Use an adjacency matrix only when the graph is dense or you need O(1) "is there an edge between u and v" lookups, since it costs O(V²) space.

The template (reproduce from memory)

from collections import defaultdict

# 1) Build an adjacency list from an edge list
def build_graph(n, edges, directed=False):
    adj = defaultdict(list)
    for u, v in edges:
        adj[u].append(v)
        if not directed:
            adj[v].append(u)
    return adj

# 2) Grid neighbours on the fly (no explicit graph needed)
DIRS = [(-1, 0), (1, 0), (0, -1), (0, 1)]   # up, down, left, right
def neighbors(r, c, rows, cols):
    for dr, dc in DIRS:
        nr, nc = r + dr, c + dc
        if 0 <= nr < rows and 0 <= nc < cols:
            yield nr, nc

# 3) State-space graph: generate a node's neighbours lazily
def state_neighbors(word, word_set):
    for i in range(len(word)):
        for ch in "abcdefghijklmnopqrstuvwxyz":
            cand = word[:i] + ch + word[i+1:]
            if cand != word and cand in word_set:
                yield cand

Composition — how a Hard is built from this pattern

Hards are usually two patterns stacked. Word Ladder (Hard 127) composes graph modeling (this lesson) with hashing (Lesson 5) and a plain shortest-path traversal.

Show the decomposition (try it yourself first)

Piece 1 — graph modeling (this lesson): each word is a node; two words are adjacent when they differ by exactly one letter. "Shortest transformation" = shortest path on this graph.

Piece 2 — hashing (Lesson 5) to make edges cheap: the naive way to find neighbours is to compare every pair of words, O(N²·L). Instead, put the whole word list in a set for O(1) membership, and generate a word's neighbours by trying every single-letter change and checking set membership — O(L·26) per word. Hashing is what makes the edge generation affordable; without it the modeling is correct but too slow.

Piece 3 — unweighted shortest path by BFS: every edge costs one step, so BFS from the start word finds the fewest transformations. (You will formalise BFS-as-shortest-path in Lessons 21 and 23; here it is just "explore level by level.")

from collections import deque

def ladderLength(beginWord, endWord, wordList):
    words = set(wordList)                 # Piece 2: hashing for O(1) lookup
    if endWord not in words:
        return 0
    q = deque([(beginWord, 1)])
    seen = {beginWord}
    while q:
        word, steps = q.popleft()
        if word == endWord:
            return steps
        for i in range(len(word)):        # Piece 1: generate one-letter neighbours
            for ch in "abcdefghijklmnopqrstuvwxyz":
                cand = word[:i] + ch + word[i+1:]
                if cand in words and cand not in seen:
                    seen.add(cand)
                    q.append((cand, steps + 1))
    return 0

The Hard = (model words-as-nodes) + (hashing to generate edges fast) + (level-by-level traversal). Name the pieces and no single piece is hard.

Reference card — Graph Modeling

The compressed version. If you've forgotten this weeks from now, re-reading just this section should reload it.

The recognition question

Ask: "What is the state, and what are the legal moves from a state?" If you can name both, the problem is a graph — the state is a node, the move is an edge. Deciding which traversal to run afterwards is a separate question driven by what is asked (reachability, components, ordering, shortest path).

Common disguises

  • Grid. Each cell is a node; neighbours are the 4 (or 8) adjacent cells. Compute neighbours on the fly with direction offsets; don't build an explicit list.
  • State space. Each configuration (word, lock combo, board) is a node; each legal operation is an edge. Generate neighbours lazily — the full space is often huge.
  • Dependencies. "A before B" is a directed edge A → B; leads to ordering/topological problems.
  • Pairwise links. Related pairs are edges; questions about groups or "are these connected" are connected-components questions.

Representation

Default to an adjacency list (dict: node → list of neighbours), O(V + E) space. Use an adjacency matrix only for dense graphs or O(1) edge-existence checks (O(V²) space).

Templates

# edge list -> adjacency list
adj = defaultdict(list)
for u, v in edges:
    adj[u].append(v)

        ...                   # (nr, nc) is a neighbour
