Iterative traversal — simulate the recursion stack by hand

Recursive tree traversal (Lesson 16) hides a stack: the call stack. Three kinds of follow-up force you to make that stack explicit — an interviewer asks for the traversal "without recursion", a problem needs you to pause and resume a traversal between external calls (a tree iterator), or the tree is deep enough that recursion would blow the stack. This lesson shows the one idea behind all three: a loop plus your own stack reproduces exactly what the call stack was doing, and the only thing that changes between preorder, inorder, and postorder is when you record a node relative to pushing its children.

Deriving iterative inorder from the call stack

Take inorder traversal without recursion. The recursive version is three lines: recurse left, visit node, recurse right. The machine runs this on a hidden stack of paused calls — so to remove recursion, you just maintain that stack yourself.

Derive it

Watch what the call stack actually does. Recursive inorder, standing at a node, immediately dives left, left, left — pushing a paused call at each step — until it hits None. Only then does the deepest paused call resume, visit its node, and turn right. So the explicit version is: push the entire left spine onto a stack, then pop one, visit it, and move to its right child — at which point you push that right child's left spine, and repeat.

def inorder(root):
    stack, node, out = [], root, []
    while node or stack:
        while node:            # push the whole left spine
            stack.append(node)
            node = node.left
        node = stack.pop()     # deepest unvisited node
        out.append(node.val)   # VISIT here = inorder
        node = node.right      # then turn right
    return out

The insight (= the pattern): the stack holds exactly the ancestors whose "visit the node" step has not happened yet — the same frames the call stack would hold. "Dive left pushing, pop and visit, turn right" is the literal unrolling of the recursion. Nothing clever is invented; the recursion is just made visible so you can step it one node at a time.

The three orders differ only in WHEN you record the node

  • Preorder (node, left, right) is the easiest iterative traversal: push the root, then loop — pop a node and record it immediately, then push its right child and left child (right first, so left is popped first). Because you record on the way down, you never need the left-spine trick.
  • Inorder (left, node, right) is the derivation above: record a node only after its entire left subtree is done, i.e. when you pop it.
  • Postorder (left, right, node) records a node last. The cleanest route is to run a modified preorder that visits node, then right, then left, and reverse the result at the end — because reversed "(node, right, left)" is exactly "(left, right, node)". A one-stack version with a "last visited" pointer also works, but the reverse trick is the one to remember under pressure.

When to reach for iterative traversal, and why it works

Reach for an explicit stack when a traversal must be pausable — the defining case is a tree iterator (next() / hasNext() over inorder), where control returns to the caller between nodes and recursion simply cannot model "stop here and come back." You also reach for it when an interviewer explicitly asks for "no recursion", or when the tree could be pathologically deep (a near-linked-list tree would overflow the language's call stack, and an explicit stack on the heap avoids that). It works because recursion is a stack of paused frames; replacing the implicit call stack with an explicit list you push and pop reproduces the identical visit order, and gives you a handle to freeze and resume the traversal that a recursive function never exposes.

Do not reach for it by default: when you simply need to walk the whole tree once and compute a value, recursive DFS (Lesson 16) is shorter and clearer, and you should prefer it. The iterative form earns its extra bookkeeping only when pausability, an explicit "no recursion" constraint, or depth safety is actually required.

The template

# Preorder — record on the way down
def preorder(root):
    if not root: return []
    stack, out = [root], []
    while stack:
        node = stack.pop()
        out.append(node.val)
        if node.right: stack.append(node.right)   # push right first...
        if node.left:  stack.append(node.left)    # ...so left pops first
    return out

# Inorder — record when popped (after the left spine)
def inorder(root):
    stack, node, out = [], root, []
    while node or stack:
        while node:
            stack.append(node); node = node.left
        node = stack.pop()
        out.append(node.val)
        node = node.right
    return out

# Postorder — modified preorder (node,right,left) then reverse
def postorder(root):
    if not root: return []
    stack, out = [root], []
    while stack:
        node = stack.pop()
        out.append(node.val)
        if node.left:  stack.append(node.left)    # left first...
        if node.right: stack.append(node.right)   # ...so right pops first
    return out[::-1]                              # reverse (node,right,left) -> (left,right,node)

# BST Iterator — a PAUSABLE inorder: the stack IS the saved state between next() calls
class BSTIterator:
    def __init__(self, root):
        self.stack = []
        self._push_left(root)
    def _push_left(self, node):
        while node:
            self.stack.append(node); node = node.left
    def next(self):
        node = self.stack.pop()
        self._push_left(node.right)   # resume into the right subtree
        return node.val
    def hasNext(self):
        return bool(self.stack)

Composition — how a Hard is built from this pattern

Binary Search Tree Iterator (Medium 173, but the O(h)-space constraint makes it genuinely hard) — link — composes iterative inorder (this lesson) with the BST "inorder = sorted" property (Lesson 18), under a space constraint that rules out the easy answer.

Show the decomposition (try it yourself first)

The ask: build an iterator over a BST that returns the next-smallest value on each next() call, with next() and hasNext() running in average O(1) and using only O(h) memory (h = tree height).

The lazy answer that is disallowed: inorder the whole tree into a list up front and index through it — that is O(n) space, which the O(h) constraint forbids. The constraint is the whole difficulty.

Piece A — inorder = sorted (Lesson 18): next-smallest means "next in inorder order", so the iterator is really a paused inorder traversal.

Piece B — the stack IS the paused state (this lesson): keep only the left-spine stack from the iterative inorder. At construction, push the left spine of the root — that is at most h nodes, giving O(h) space. Each next() pops the top (the current smallest unvisited node), then pushes the left spine of that node's right child so the next-smallest is ready on top. Across the whole traversal each node is pushed and popped once, so next() is amortized O(1).

The Hard = (inorder gives sorted order) + (the explicit left-spine stack as freeze-able traversal state, bounded by height). The O(h) bound falls out for free because a left spine is never longer than the tree's height. Name the pieces and the Hard stops being hard.

Reference card — Iterative traversal

When to use it, and why

Use an explicit stack when a traversal must be pausable (a tree iterator with next()/hasNext()), when "no recursion" is required, or when the tree could be deep enough to overflow the call stack. It works because recursion already runs on a stack of paused frames; maintaining that stack yourself reproduces the identical order and hands you a freeze-and-resume handle recursion never exposes. For a plain one-shot walk, prefer recursive DFS (Lesson 16).

The one idea

A loop plus your own stack = the call stack unrolled. The stack holds the ancestors whose node-visit step has not happened yet.

Order = when you record the node

  • Preorder: record on pop, push right then left. Record on the way down.
  • Inorder: push the whole left spine, pop+record, turn right. Record after the left subtree.
  • Postorder: run modified preorder (node, right, left) and reverse the output.

Template (inorder, and the pausable iterator)

stack, node = [], root
while node or stack:
    while node: stack.append(node); node = node.left
    node = stack.pop(); visit(node); node = node.right

# iterator: keep only the stack; next() = pop, then push-left(node.right)
