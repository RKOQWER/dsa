Subsequence DP — pick the best subsequence from one array

A whole class of questions hands you one array and asks you to choose a subsequence (keep some elements, drop the rest, order preserved) that is longest, largest, or maximal under some rule — then return that one best answer. Longest Increasing Subsequence is the archetype, and Longest String Chain, Largest Divisible Subset, Maximum Length of Pair Chain, and Russian Doll Envelopes are all the same shape. The trap is that this looks like the 1D DP of Lesson 27, but its transition does not look back a fixed step or two: it looks back at every earlier index that is allowed to come before the current one.

Deriving the subsequence shape via LIS

Take Longest Increasing Subsequence: given an array nums, find the length of the longest subsequence whose values strictly increase (elements kept in their original order, not necessarily contiguous).

Derive it

Try to make "ending here" the thing you solve for. The tempting state dp(i) = "longest increasing subsequence within nums[0..i]" fails, because to extend it you must know the last value you kept, and that single number does not record it. So pin the state to that fact instead: define the state function dp(i) = the length of the longest increasing subsequence that ends exactly at index i (i.e. nums[i] is its final, largest element). Now the last value is nums[i] by construction, which is what makes the transition writable.

Find the choice: which element comes just before i in that subsequence? The element ending at i must be preceded by some earlier index j < i whose value is smaller (nums[j] < nums[i]), or by nothing at all (the subsequence is just nums[i] itself, length 1). You do not know which j is best, so try every eligible one and keep the longest:

dp(i) = 1 + max( dp(j) for all j < i with nums[j] < nums[i] )
      = 1   if no such j exists

Compute the DP, then read the answer off all states. Fill dp(i) for i = 0..n-1 left to right; each one scans the earlier indices, so the whole thing is O(n²). The subsequence can end anywhere, so the answer is max(dp) over all i — not dp(n-1). That last point is the signature of this family: because the state is "ending exactly at i," the final answer is the best over every ending, not the value at the last index.

The transferable shape: a subsequence-optimization DP exists whenever you choose a subsequence of one array under an "is j allowed to precede i?" pairwise rule, and want the best (longest / largest-sum / largest size) such chain. The state is always "best answer ending exactly at i," the transition always scans earlier indices and keeps the ones that satisfy the rule, and the answer is always the best over all endings. Change only the pairwise rule and the quantity you optimize, and the whole family falls out.

When to reach for subsequence DP, and why

  • You are given one array and asked to keep an ordered subset (a subsequence) that is longest, largest, or maximal under a rule relating each kept element to the previous kept one. Because validity depends on a pairwise relation between a candidate element and its predecessor, you cannot decide element i without knowing what it attaches to — so the state must fix the ending element, and the transition must consider every earlier element that could legally sit before it.
  • The look-back is unbounded: the predecessor could be any earlier index, not just the immediately previous one or two. This is the line that separates this family from the 1D DP of Lesson 27. In 1D DP the consequence of a choice reached a bounded number of neighbours, giving O(n); here each state scans all earlier states, giving O(n²) — and that extra scan is the price of a pairwise eligibility rule.
  • You must return one optimal value (or reconstruct one optimal subsequence), not count or enumerate all of them. Keep max for the best length or sum; switch the combine to + only if the question flips to "how many longest ones." If you must output the actual elements, store a parent pointer at each state and walk it back from the best ending — reconstruction, not a different DP.

The template

# Longest Increasing Subsequence — O(n^2)
def lengthOfLIS(nums):
    n = len(nums)
    dp = [1] * n                      # dp[i] = longest increasing subseq ENDING at i
    for i in range(n):
        for j in range(i):            # scan ALL earlier indices
            if nums[j] < nums[i]:     # the pairwise eligibility rule
                dp[i] = max(dp[i], dp[j] + 1)
    return max(dp)                    # answer is best over ALL endings

# Same template, reconstructing the actual subsequence via parent pointers
def getLIS(nums):
    n = len(nums)
    dp = [1] * n
    parent = [-1] * n
    for i in range(n):
        for j in range(i):
            if nums[j] < nums[i] and dp[j] + 1 > dp[i]:
                dp[i], parent[i] = dp[j] + 1, j
    best = max(range(n), key=lambda i: dp[i])
    seq = []
    while best != -1:
        seq.append(nums[best]); best = parent[best]
    return seq[::-1]

# O(n log n) LIS length only — patience sorting; keep for interviews, derive separately
import bisect
def lengthOfLIS_fast(nums):
    tails = []                        # tails[k] = smallest tail of an increasing subseq of length k+1
    for x in nums:
        i = bisect.bisect_left(tails, x)
        if i == len(tails): tails.append(x)
        else: tails[i] = x
    return len(tails)

The trap — looks like it, isn't

Longest Continuous Increasing Subsequence (Easy) asks for the longest increasing run of adjacent elements. It reads almost identically to LIS, but "continuous" means the predecessor is forced to be i-1 — there is no choice of which earlier index to attach to. That collapses the unbounded scan back to a bounded one-step look-back, so it is a 1D DP (Lesson 27) solvable in O(n), not an O(n²) subsequence DP. The discriminator is one word: if the kept elements must be contiguous, the predecessor is fixed and you are in Lesson 27; if they may be any ordered subset, the predecessor is a choice and you are here.

Composition — a Hard built from subsequence DP + earlier patterns

Russian Doll Envelopes (Hard) — link. Composes this subsequence DP with a sorting reduction (Part 2) that turns a 2D nesting problem into a 1D LIS.

Show the decomposition (try it yourself first)

The problem: each envelope has a width and height; one fits inside another only if both its width and height are strictly larger. Find the longest chain of nested envelopes.

Pattern A — sort to remove one dimension (Part 2): sort by width ascending, and for equal widths sort by height descending. After this sort, a valid nesting chain must have strictly increasing height, because the descending-height tiebreak prevents two equal-width envelopes from ever both being chosen in an increasing-height run. The width constraint is now automatically handled by the sort order.

Pattern B — LIS on the remaining dimension (this lesson): run Longest Increasing Subsequence on the heights alone. The state, transition, and "max over all endings" are exactly the template above — the only new idea is that the sort pre-processes the problem down to one dimension so the pairwise rule becomes the plain nums[j] < nums[i] you already know.

The Hard = (a sort that collapses 2D nesting to 1D increasing) + (the LIS template on what is left). Both are tools you already have; only the tiebreak direction is the trick to see.

Reference card — Subsequence-optimization DP (LIS family)

When, and why

Use it when you are given one array and must keep an ordered subset (a subsequence) that is longest, largest-sum, or maximal under a pairwise rule relating each kept element to the one before it, and you must return one optimal answer. Because validity is a pairwise relation to the predecessor, the state must fix the ending element and the transition must scan every earlier eligible index — giving O(n²), the price of an unbounded look-back. This is the pattern's dividing line from 1D DP (Lesson 27), where the look-back is bounded and the cost is O(n).

The three acts, specialized

Define the state function: dp(i) = the best answer (longest length, largest sum, …) for a valid subsequence that ends exactly at index i, so that the last kept element is nums[i] and the pairwise rule becomes checkable. The smallest state is a single element alone, value 1 (or nums[i] for a sum). Define the transition: over all earlier j < i that satisfy the eligibility rule (nums[j] < nums[i] for increasing, nums[i] % nums[j] == 0 for divisible, "fits inside" for chains), combine with max for best or + for how-many, then add this element's contribution. Compute the DP: fill left to right in O(n²); the answer is the best over all endings, max(dp), not dp(n-1); store a parent pointer per state if you must output the actual subsequence.

Template

dp = [1] * n                       # best ending exactly at i
for i in range(n):
    for j in range(i):             # scan ALL earlier indices
        if eligible(j, i):         # the pairwise rule
            dp[i] = max(dp[i], dp[j] + contribution(i))
return max(dp)                     # best over ALL endings
