Graph BFS & DFS — components, flood fill, and the one rule that keeps them linear

Once a problem is modeled as a graph (Lesson 20), you traverse it. BFS and DFS are the same traversal with one difference — the order in which you pull work off your pile. This lesson derives why a visited set is what makes any graph traversal O(V + E), when to prefer BFS over DFS, and the connected-components / flood-fill shape that shows up everywhere.

Deriving the traversal — and why the visited set is non-negotiable

Derive it

The task: starting from a node, reach every node reachable from it.

First attempt: "go to a neighbour, then its neighbours, and so on." But graphs have cycles and multiple paths to the same node. Without bookkeeping you revisit nodes forever — in a cycle you never terminate, and even in a DAG you re-expand the same node along every path, which blows up exponentially. This is the same waste you saw in Word Ladder's brute force: re-deriving the future of a node you've already handled.

Spot the waste: a node's reachable set does not depend on how you arrived at it. So the first time you touch a node you should record it and never process it again.

The insight (= the pattern): keep a visited set. Maintain a pile of "nodes to process." Pop one, and for each neighbour not yet visited, mark it visited and push it. Because every node is pushed at most once and each edge is examined at most twice (once from each endpoint), the whole traversal is O(V + E). The visited set is the single thing that converts a potentially infinite/exponential walk into a linear one.

The only real choice left is what the pile is. A queue (FIFO) processes nodes in order of distance from the start — that is BFS, and it explores level by level. A stack (LIFO), or equivalently recursion, dives as deep as possible first — that is DFS. Same algorithm, same visited set, same O(V + E); only the pile's discipline differs.

The deeper principle (so it transfers)

Every graph traversal is "pop from a pile, mark neighbours visited, push them." The data structure you use for the pile decides the exploration order, and the exploration order is what you choose based on the question. If you need the fewest edges to reach something, you want level-by-level order, so use a queue (BFS). If you only need to know whether something is reachable, or you want to process a node fully before its siblings (subtree sizes, cycle detection, backtracking-style work), a stack or recursion (DFS) is simpler. Neither is faster in the big-O sense — they differ in order and in memory shape.

When to reach for BFS vs DFS, and why

Use BFS when the question is about shortest distance in an unweighted graph

Because a queue pulls nodes out in increasing order of distance from the start, the first time BFS reaches a node is guaranteed to be along a path with the fewest edges. So whenever the problem asks for the minimum number of steps, moves, or levels — and every edge counts the same — BFS gives the answer directly. It is also the natural choice when you want to process a graph in layers (for example, rotting oranges spreading one minute at a time).

Use DFS when you need to explore a whole branch before moving on

Recursion naturally finishes one subtree/branch completely before backtracking, which is exactly what you want for counting the size of a connected region, detecting a cycle by tracking the current recursion path, or any problem where a node's answer depends on fully resolving its descendants first. DFS also uses memory proportional to the longest path rather than the widest level, which can matter on tall, narrow graphs.

Connected components and flood fill are just repeated traversal

To count groups (islands, provinces, friend circles), walk every node; when you find one not yet visited, that is a new component, so increment a counter and run one traversal to mark the entire component visited. Because the visited set prevents re-entry, the number of times you start a fresh traversal equals the number of components. Flood fill is the same shape — start one traversal and recolour everything connected.

The template (reproduce from memory)

from collections import deque

# BFS — shortest #edges in an unweighted graph
def bfs(start, adj):
    visited = {start}
    q = deque([(start, 0)])          # (node, distance)
    while q:
        node, dist = q.popleft()
        for nxt in adj[node]:
            if nxt not in visited:
                visited.add(nxt)     # mark on ENQUEUE, not on dequeue
                q.append((nxt, dist + 1))
    return visited

# DFS — recursive
def dfs(node, adj, visited):
    visited.add(node)
    for nxt in adj[node]:
        if nxt not in visited:
            dfs(nxt, adj, visited)

# Count connected components
def count_components(nodes, adj):
    visited = set()
    count = 0
    for node in nodes:
        if node not in visited:
            count += 1
            dfs(node, adj, visited)
    return count

Mark a node visited when you add it to the pile, not when you pop it — otherwise the same node can be enqueued many times before it is first processed. Compact reference at the bottom.

Composition — how a Hard is built from this pattern

Making A Large Island (Hard 827) composes graph BFS/DFS component counting (this lesson) with hashing (Lesson 5) to recombine results.

Show the decomposition (try it yourself first)

The problem: you may flip exactly one 0 to 1; return the largest island possible afterwards.

Piece 1 — DFS component sizing (this lesson): first, label every existing island with a unique id and record each island's size. That is a single pass of connected-components DFS, giving a map id → size.

Piece 2 — hashing to merge without recomputing (Lesson 5): for each 0 cell, look at its up/down/left/right neighbours, collect the distinct island ids around it into a set (hashing — so the same island touched on two sides is counted once), and sum those island sizes plus one for the flipped cell. The max over all 0 cells is the answer. The set is what prevents double-counting an island that borders the cell twice.

Why brute force is worse: flipping each 0 and re-running a full island DFS is O((RC)²). Labelling once and merging via a set of neighbour ids is O(RC).

def largestIsland(grid):
    n = len(grid)
    size = {}                     # island id -> size
    island_id = 2                 # start at 2 (0 and 1 already used)

    def dfs(r, c, idx):
        if not (0 <= r < n and 0 <= c < n) or grid[r][c] != 1:
            return 0
        grid[r][c] = idx
        return 1 + dfs(r+1,c,idx) + dfs(r-1,c,idx) + dfs(r,c+1,idx) + dfs(r,c-1,idx)

    for r in range(n):            # Piece 1: label + size every island once
        for c in range(n):
            if grid[r][c] == 1:
                size[island_id] = dfs(r, c, island_id)
                island_id += 1

    best = max(size.values(), default=0)
    for r in range(n):            # Piece 2: try each 0, merge neighbour islands via a set
        for c in range(n):
            if grid[r][c] == 0:
                seen = set()
                for dr, dc in [(-1,0),(1,0),(0,-1),(0,1)]:
                    nr, nc = r+dr, c+dc
                    if 0 <= nr < n and 0 <= nc < n and grid[nr][nc] > 1:
                        seen.add(grid[nr][nc])
                best = max(best, 1 + sum(size[i] for i in seen))
    return best

The Hard = (label + size components with DFS) + (hashing a set of neighbour ids to merge sizes without recomputation).

Reference card — Graph BFS & DFS

The compressed version.

The core idea

Every traversal is: pop a node from a pile, and for each neighbour not yet visited, mark it and push it. The visited set makes it O(V + E) by ensuring each node is processed once. The pile's type sets the order: a queue → BFS (level by level), a stack/recursion → DFS (deep first).

When to use which, and why

  • BFS when you need the fewest edges/steps in an unweighted graph (the queue visits nodes in distance order, so the first arrival is shortest), or when you want to process the graph in layers.
  • DFS when a node's answer needs its whole branch resolved first (region size, cycle detection on the current path, backtracking) or when memory should scale with path length, not level width.
  • Connected components / flood fill: loop over all nodes; each unvisited node starts a new component and one traversal marks the whole group. Count of fresh starts = number of components.

Gotcha

Mark visited on enqueue/push, not on dequeue/pop, or nodes get added multiple times.

Templates

# BFS
visited = {start}; q = deque([start])
while q:
    node = q.popleft()
    for nxt in adj[node]:
        if nxt not in visited:
            visited.add(nxt); q.append(nxt)

# DFS (recursive)
def dfs(node):
    visited.add(node)
    for nxt in adj[node]:
        if nxt not in visited:
            dfs(nxt)
