Deriving sliding window from scratch

Take the cleanest case. An array of positive integers; find the longest contiguous subarray whose sum is ≤ k.

Derive it

Brute force: for every start index i, extend an end index j and sum a[i..j] until it exceeds k; track the longest. That's O(n²) because for each new start you re-sum from scratch.

Spot the waste: watch what happens between consecutive starts. When you finish start i and move to start i+1, brute force throws away everything and re-sums a[i+1..j] from zero — even though it just computed a[i..j] one step ago. The only difference between those two sums is that a[i] left. You recomputed an entire range to delete one element.

The insight (= the pattern): keep a window [left, right] and a running sum. Push right forward and add the new element. The instant the sum breaks the constraint (> k), move left forward and subtract the element leaving — shrinking until the window is valid again. Every element is added exactly once (by right) and removed at most once (by left), so the total work is O(n). The window never slides backward; that monotonic one-directional motion is the sliding-window pattern.

The deeper principle (so it transfers)

Sliding window applies when the answer is about a contiguous run of the array or string, and when extending or shrinking that run changes your running state incrementally — you can update the state in O(1) as an element enters or leaves, instead of recomputing it. The second condition is the real gatekeeper: if adding an element forces you to rescan the whole window (so there's no cheap incremental update), sliding window gives you nothing. The classic enabling case is "the quantity only ever grows as you add elements and only shrinks as you remove them," which is why it pairs so naturally with monotonic constraints like a sum of positive numbers or a count of distinct characters.

When to use it, and the two flavors

Fixed-size window

You use a fixed window when the problem names an exact length — "every subarray of size k", "the maximum sum of k consecutive elements", "averages of all windows of width k." You slide a window of constant width across the array: each step you add the element entering on the right and subtract the element falling off the left, so the window's aggregate updates in O(1). It works because the width is pinned, so you never decide how far to shrink — you just march the fixed frame one step at a time.

Variable-size window

You use a variable window when the problem asks for the longest or shortest run of consecutive elements that obeys some rule — "longest substring with at most K distinct characters", "smallest subarray with sum ≥ target", "longest substring without repeating characters." You keep two markers, left and right, marking the stretch you are currently looking at. You move right forward to make the stretch bigger. The moment the stretch breaks the rule, you move left forward to chop elements off the start until the rule holds again. Then you keep going.

Why moving left is always the right fix: if your current stretch already breaks the rule, making it even longer can only make things worse, never better — so the only way back to a legal stretch is to make it shorter from the left. Concretely: suppose the rule is "sum ≤ 10" and your window [4, 5, 3] sums to 12, which is too big. Adding another number on the right makes the sum even bigger, so that cannot help; your only move is to drop the 4 on the left. That is the whole idea — once you are over the line, growing can't save you, only shrinking can. Because of that, you never have to second-guess the shrink: it is always the correct repair.

"Longest / shortest" makes me think DP or greedy — how do I know it's a window?

Good instinct to check, because "longest/shortest" really does show up in DP, greedy, and sliding window. The word alone decides nothing. Sliding window applies only when all three of these are true:

  1. The answer is a contiguous chunk — a subarray or substring, with the elements next to each other. Not a subsequence where gaps are allowed.
  2. You can test a window's validity cheaply and incrementally — when you add one element on the right or drop one on the left, you can update "is this window still valid?" in about O(1), without rescanning the whole window. (A running sum, a character-frequency map, a count of distinct characters — all cheap to update.)
  3. Validity is monotonic — if a window is invalid because it is too big, every bigger window is also invalid. This is what lets you shrink with confidence instead of exploring every possibility.

If any one of the three fails, it is not a sliding window.

The single fastest discriminator — trust this word, not "longest": if the problem says subarray or substring (contiguous), lean sliding window. If it says subsequence (gaps allowed), lean dynamic programming. "Longest Repeating Character Replacement" says substring → contiguous → window. "Longest Increasing Subsequence" says subsequence → gaps → DP. Same word "longest", opposite tool, decided entirely by substring-vs-subsequence.

Versus greedy specifically: greedy makes one locally-best choice at each step and never undoes it. A sliding window does undo — it removes elements it previously added when it shrinks. So if the problem needs you to sometimes take things back out, it is a window, not pure greedy.

How to tell which flavor you need

Read the constraint on the window size. If the size is given to you as a fixed number, it is a fixed window. If the size is the thing you are optimizing (you want the longest or shortest window meeting some condition), it is a variable window. That single question — "is the window width given, or is it the answer?" — picks the flavor every time.

The template (reproduce from memory)

# Fixed-size window: max sum of any k consecutive elements
def max_sum_k(a, k):
    window = sum(a[:k])
    best = window
    for right in range(k, len(a)):
        window += a[right] - a[right - k]   # add entering, drop leaving
        best = max(best, window)
    return best

# Variable-size window: longest subarray with sum <= k (positives)
def longest_le_k(a, k):
    left = 0
    total = 0
    best = 0
    for right in range(len(a)):
        total += a[right]                   # grow right
        while total > k:                    # shrink left until valid
            total -= a[left]
            left += 1
        best = max(best, right - left + 1)
    return best

Composition — how a Hard is built from this pattern

Minimum Window Substring (Hard) — link — composes a variable-size sliding window (this lesson) with a hashing frequency count (the counting idea you already use with hashmaps, formalized in Lesson 5).

Show the decomposition (try it yourself first)

The ask: smallest window in s that contains every character of t (with multiplicity). "Smallest contiguous window meeting a condition" is the variable-window signal.

Piece A — variable window: grow right until the window is valid (contains all of t), then shrink left as far as it can go while staying valid, recording the best length. This is exactly the grow-right / shrink-left machine from this lesson.

Piece B — frequency counting: to decide "does the window contain all of t" in O(1) per step, keep a need-count map of t and a have counter of how many required characters are currently satisfied. As a character enters or leaves, bump the counts and compare — never rescan the window. That is the hashmap counting idea.

The Hard is just the window loop with an O(1) validity check powered by two counters. Neither half is hard alone — naming the two halves is the whole method.

from collections import Counter
def minWindow(s, t):
    need = Counter(t)
    missing = len(t)
    left = start = end = 0
    for right, ch in enumerate(s, 1):     # right is 1-based end
        if need[ch] > 0:
            missing -= 1
        need[ch] -= 1
        while missing == 0:               # window valid: try to shrink
            if end == 0 or right - left < end - start:
                start, end = left, right
            need[s[left]] += 1
            if need[s[left]] > 0:
                missing += 1
            left += 1
    return s[start:end]

Reference card — Sliding Window

The compressed version. Re-reading just this should reload the pattern.

When to use it, and why

  • Fixed-size window. The problem names an exact window width k and asks for an aggregate over every such window. Slide a constant-width frame, adding the entering element and subtracting the leaving one, so each window's value updates in O(1).
  • Variable-size window. The problem asks for the longest or shortest contiguous stretch satisfying a constraint. Grow the window with right; when the constraint breaks, shrink with left until it holds again. Works because validity is monotonic — a too-big window can't be fixed by growing.

The one-line reason it works

Each element enters the window once and leaves at most once, and the running state updates incrementally as elements enter and leave — so the whole scan is O(n) instead of the O(n²) of re-summing every subarray.

Discrimination test (is it a window, or DP/greedy?)

"Longest/shortest" alone does not mean sliding window — it also appears in DP and greedy. It is a window only when all three hold: (1) the answer is a contiguous subarray/substring, not a subsequence; (2) you can update "is this window valid?" cheaply as one element enters or leaves, without rescanning; (3) validity is monotonic — a too-big invalid window stays invalid when grown. Fastest cue: the word "subarray/substring" → window, the word "subsequence" → DP. Versus greedy: a window undoes choices when it shrinks, whereas greedy never takes anything back.

Templates (Python)

# fixed window
window = sum(a[:k]); best = window
for right in range(k, len(a)):

# variable window
left = 0; agg = init
for right in range(len(a)):
    agg = add(agg, a[right])
    while not valid(agg):
        agg = remove(agg, a[left]); left += 1
    best = better(best, right - left + 1)

Complexity and classic problems

Time O(n), space O(1) or O(alphabet) when a frequency map is involved. Classic set: Longest Substring Without Repeating Characters (Medium), Minimum Size Subarray Sum (Medium), Permutation in String (Medium), Minimum Window Substring (Hard, composed with frequency counting).
