Deriving the index-as-hash trick from scratch

Take the cleanest case. An array of length n contains numbers in the range 1..n with one missing; find the missing number using O(1) extra space.

Derive it

Brute force / obvious fix: put every value into a hashset, then scan 1..n for the one absent. That's O(n) time but O(n) extra space — and the problem forbids extra space.

Spot the waste: the hashset is storing "is value v present?" as its own structure. But you already have an array of length n, and the values are themselves in 1..n — the exact index range of the array. You're allocating a second container to record presence information that could ride on the array you already have.

The insight (= the pattern): the array is the hashmap. Use each value to pick a slot and mark presence there — for example, for each value v, flip the sign of a[v-1] to record "v was seen." After one pass, the slot that is still positive points to the value never marked: the missing one. Or, more directly, place each value at its home index (value v belongs at index v-1) by swapping until everything is home — then the first index whose occupant isn't its home value reveals the missing/duplicate. Either way, you encode the auxiliary information inside the input itself, achieving O(1) extra space. Using position as a key is the pattern.

The deeper principle (so it transfers)

When the values of an array happen to fall in the same range as its indices (typically 0..n-1 or 1..n), the array can serve as its own hashmap: a value tells you a slot, and you mark that slot — by sign-flipping, by swapping the value into its home position, or by adding a multiple of n. This is what lets "find the missing / duplicate / first-missing-positive" problems hit O(1) space. A sibling idea is the in-place partition: when you must rearrange an array into a few known categories without extra space (all zeros, then ones, then twos), you move boundary pointers inward and swap elements into their region, which is the Dutch national flag scheme. And for rotation, the reversal identity — reverse the whole array, then reverse the two pieces — rotates in place because reversing twice around a split point is exactly a cyclic shift.

When to use each trick, and why

Index-as-hash (cyclic sort / sign marking)

You reach for this when the array's entries lie in 1..n (or 0..n-1) and the problem asks for a missing, duplicate, or misplaced value under an O(1)-space constraint. You either send each value to its home index by swapping, or mark its home slot (sign flip), then scan for the slot that is wrong. It works because the value-range-equals-index-range coincidence lets each value address a unique slot, so presence can be recorded inside the array with no new memory.

Dutch national flag (three-way in-place partition)

You reach for this when you must sort or group elements into a small fixed number of categories (classically 0/1/2, or less-than / equal / greater-than a pivot) in one pass and in place. You maintain three regions with a low pointer, a mid scanner, and a high pointer, swapping each scanned element into its correct region. It works because every element is examined once and sent to its final region immediately, so a single linear sweep produces the partition without any auxiliary array.

Reversal trick for rotation

You reach for the reversal trick when you must rotate an array (or string) by k positions in place. You reverse the entire array, then reverse the first k elements and the remaining n−k elements separately. It works because reversing the whole array puts the elements in the right blocks but backwards, and the two local reversals correct the order within each block, yielding the rotation with O(1) extra space.

The template (reproduce from memory)

# Index-as-hash by cyclic placement: find the missing number in 1..n
def find_missing(a):
    n = len(a)
    i = 0
    while i < n:
        home = a[i] - 1                         # value v belongs at index v-1
        if 1 <= a[i] <= n and a[i] != a[home]:
            a[i], a[home] = a[home], a[i]       # swap into home, don't advance
        else:
            i += 1
    for idx in range(n):
        if a[idx] != idx + 1:
            return idx + 1
    return n + 1

# Dutch national flag: sort an array of 0s, 1s, 2s in place
def sort_colors(a):
    low, mid, high = 0, 0, len(a) - 1
    while mid <= high:
        if a[mid] == 0:
            a[low], a[mid] = a[mid], a[low]; low += 1; mid += 1
        elif a[mid] == 1:
            mid += 1
        else:
            a[mid], a[high] = a[high], a[mid]; high -= 1   # don't advance mid

# Rotate right by k using the reversal trick
def rotate(a, k):
    n = len(a); k %= n
    a.reverse()
    a[:k] = reversed(a[:k])
    a[k:] = reversed(a[k:])

Composition — how a Hard is built from this pattern

First Missing Positive (Hard) — link — demands O(1) space, which forces the index-as-hash trick (this lesson), combined with the same "find where reality disagrees with the ideal arrangement" scan you used for the missing-number derivation.

Show the decomposition (try it yourself first)

The ask: find the smallest positive integer absent from an unsorted array, in O(n) time and O(1) extra space. The O(1)-space clause is the loud signal: a hashset is forbidden, so the array must be its own hashmap.

Piece A — index-as-hash placement: the answer must lie in 1..n+1, so only values in 1..n matter. Cyclically place each such value v at index v-1 by swapping, ignoring anything out of range or already home. This is exactly the cyclic-sort move from this lesson.

Piece B — scan for the first disagreement: after placement, walk the array; the first index idx whose occupant isn't idx+1 means idx+1 is missing. If every slot is correct, the answer is n+1. This is the "first slot where reality breaks the ideal" scan from the derivation.

The Hard = (cyclic index-as-hash placement) + (first-mismatch scan), with the whole thing pinned to O(1) space by refusing to allocate. Name the pieces and the famous hard becomes routine.

def firstMissingPositive(a):
    n = len(a)
    i = 0
    while i < n:
        v = a[i]
        if 1 <= v <= n and a[v - 1] != v:
            a[i], a[v - 1] = a[v - 1], a[i]
        else:
            i += 1
    for idx in range(n):
        if a[idx] != idx + 1:
            return idx + 1
    return n + 1

Reference card — Cyclic & In-place Array Tricks

When to use each, and why

  • Index-as-hash / cyclic sort. Values lie in 1..n (or 0..n-1) and you must find a missing/duplicate/misplaced value in O(1) space. Send each value to its home index or sign-mark its slot, then scan for the wrong slot. The value-range-equals-index-range coincidence lets the array record presence itself.
  • Dutch national flag. Partition into a few fixed categories in one in-place pass. Low/mid/high pointers swap each element into its region. One linear sweep, no auxiliary array.
  • Reversal trick. Rotate an array/string by k in place. Reverse the whole thing, then reverse the first k and the rest. Two reversals around the split produce a cyclic shift.

The one-line reason it works

These tricks all exploit that the input array already has enough structure (index range matching value range, or reversibility) to carry the auxiliary information itself, so no extra memory is needed.

Discrimination test

The index-as-hash trick only applies when values are confined to the index range; if values can be arbitrary, you need a real hashset. The loud trigger for these tricks is an explicit "O(1) extra space" or "modify in place" requirement — without that constraint, a plain hashmap or extra array is simpler and equally fast.
