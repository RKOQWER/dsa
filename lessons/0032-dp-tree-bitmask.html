DP on Trees & Bitmask DP — two state shapes you haven't met yet

Two DP flavors that confuse people because the state looks unusual. In tree DP the subproblem is "a subtree rooted at a node," and you often carry an extra flag for the node's own choice. In bitmask DP the state is "which elements of a small set have been used," encoded as the bits of an integer. Both are ordinary DP once you accept the odd-looking state.

Deriving tree DP

Take House Robber III: houses form a binary tree, you cannot rob a node and its direct child, maximize the take. It's House Robber (Lesson 27) on a tree instead of a line.

Derive it — the per-node choice with a flag

Find the choice at a node: rob this node or skip it — same two options as the linear version. The consequence propagates to children:

  • If you rob this node, you gain its value but must skip both children, so you take each child's best-when-the-child-is-skipped.
  • If you skip this node, each child is free to be robbed or not, so you take each child's overall best.

So each node should return two numbers: the best total for its subtree if the node is robbed, and the best if it is not. The parent combines the children's two-number bundles. This is exactly bottom-up tree DFS (Lesson 16), where the "info returned up" is a tiny DP state.

def dfs(node):
    if not node: return (0, 0)          # (rob_this, skip_this)
    L_rob, L_skip = dfs(node.left)
    R_rob, R_skip = dfs(node.right)
    rob_this  = node.val + L_skip + R_skip
    skip_this = max(L_rob, L_skip) + max(R_rob, R_skip)
    return (rob_this, skip_this)

There is no explicit cache here because a tree has no overlapping subproblems across siblings — each subtree is visited once. The "DP" is the per-node optimal-substructure combine, not memoization. That's the defining feature of tree DP: the recursion structure is the tree itself, and the state is a small bundle per node.

Deriving bitmask DP

Take the Traveling-Salesman-style problem: n cities (n small, ~15), visit all exactly once, minimize path cost. Brute force tries all n! orderings.

Derive it — the set of used elements IS the state

Spot the waste in n! brute force: two different orderings that visit the same set of cities and end at the same city have identical remaining subproblems — the future only depends on "which cities are still unvisited" and "where I am now," not the exact order I visited the earlier ones. That's overlap.

The insight: encode "which cities have been visited" as the bits of an integer mask (bit c set = city c visited). The state is (mask, current_city). There are only 2ⁿ · n such states, far fewer than n! orderings.

from functools import cache
def tsp(dist, n):
    @cache
    def dp(mask, u):                     # visited set = mask, currently at u
        if mask == (1 << n) - 1:
            return dist[u][0]            # all visited, return to start
        best = float('inf')
        for v in range(n):
            if not (mask & (1 << v)):    # v not yet visited
                best = min(best, dist[u][v] + dp(mask | (1 << v), v))
        return best
    return dp(1, 0)                      # start at city 0, mask with bit 0 set

Why bits: a subset of a small universe is naturally an integer; set/clear/test are single bit operations (Lesson 13), and the integer is a perfect cache key. The tiny constraint (n ≤ ~20) is the dead giveaway that an exponential-in-n but polynomial-in-2ⁿ approach is intended.

When to reach for each, and why

  • Tree DP: the input is a tree (or a graph you've made acyclic) and the answer for a node depends on optimal answers of its subtrees, often with a local choice (include/exclude the node, color it, match it). Because each subtree is an independent smaller instance and is visited once, a single post-order DFS returning a small state bundle computes everything in O(nodes) — you never need an explicit cache, the tree structure supplies the ordering.
  • Bitmask DP: you must consider all subsets or all orderings of a small set (n up to roughly 20), and the future depends only on which elements are used, not their order. Encoding the used set as bits gives 2ⁿ states instead of n! orderings, and bit operations make transitions O(1) per element. The small-n constraint is the signal; if n were large, no exponential-in-n method would pass and it isn't bitmask DP.

Composition — a Hard built from bitmask DP + earlier patterns

Shortest Path Visiting All Nodes (Hard) — link. Composes bitmask state with BFS shortest path on an unweighted graph (Lesson 23) and graph modeling (Lesson 20).

Show the decomposition (try it yourself first)

The problem: given an undirected graph, find the length of the shortest walk that visits every node (you may revisit nodes and reuse edges, and may start anywhere).

Pattern A — graph modeling with an enriched node (Lesson 20): a plain "current node" state is not enough, because the answer depends on which nodes you've already covered. Enrich the state to (current_node, visited_mask) — the bitmask records coverage. This is the bitmask idea from this lesson used as part of the graph's state.

Pattern B — BFS for shortest path on unweighted edges (Lesson 23): every edge costs 1, so BFS over the enriched state space finds the shortest number of steps. Start BFS from all nodes simultaneously (each with only its own bit set), and stop when any state's mask becomes all-ones.

The Hard = (bitmask coverage state) + (graph modeling to enrich the node) + (unweighted BFS for shortest steps). The bitmask is this lesson; the BFS and modeling are Lessons 20 and 23. No single piece is hard; recognizing that the state is (node, mask) is the unlock.

Reference card — Tree DP & Bitmask DP

Tree DP — when and why

Use it when the input is a tree and a node's answer depends on its subtrees' optimal answers, often with a local include/exclude choice. One post-order DFS returning a small state bundle per node computes everything in O(nodes); the tree supplies the dependency order, so no explicit cache is needed.

Bitmask DP — when and why

Use it when you consider all subsets or orderings of a small set (n ≲ 20) and the future depends only on which elements are used. Encode the used set as integer bits for 2ⁿ·(extra) states instead of n! orderings; bit ops give O(1) transitions. Small n is the signal.
