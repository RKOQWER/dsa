Deriving the hashmap move from scratch

Take the cleanest case. Unsorted array; return indices of the two numbers that sum to a target.

Derive it

Brute force: for each element x, scan the rest of the array looking for target − x. That inner scan is O(n), so the whole thing is O(n²).

Spot the waste: the inner loop is doing a search — "is target − x present, and where?" — against elements you have already walked past. You are re-searching the same seen elements again and again. The repeated cost is membership-and-location lookup over a growing set of things you've already seen.

The insight (= the pattern): a hashmap answers "have I seen value v, and at what index?" in O(1). So walk once; for each x, ask the map for its complement target − x. If present, you're done; otherwise record x → its index and continue. The O(n) inner search collapses to an O(1) lookup, so the whole algorithm is O(n). The hashmap converted "search the past" into "recall the past instantly."

The deeper principle (so it transfers)

Any time your brute force contains an inner loop whose only job is to find or count something among elements you have already processed, a hashmap can replace that inner loop with an O(1) recall. The art is choosing the right key: the key must be whatever makes two items "the same" for the purpose of the problem. If equality is on raw value, the key is the value. If two strings count as equal when they're anagrams, the key is their canonical form (sorted letters, or a letter-count signature). Picking the key that encodes the problem's notion of sameness is the whole skill; the lookup is then automatic.

When to use it, and the four everyday moves

Seen-set for membership and duplicates

You use a set when the only question is "have I encountered this exact thing before?" — detecting duplicates, checking whether a complement exists, or testing membership in a reference collection. You add each item as you go and test future items against the set. It works because a set answers presence in O(1), turning a nested "is it anywhere earlier" scan into a single pass.

Frequency map for counting

You use a frequency map when the answer depends on how many times each value appears — finding the majority element, checking whether two strings use the same letters, or detecting whether a window contains enough of each required character. You tally counts in one pass, then read or compare the tallies. It works because counting-by-key replaces repeated re-counting scans with a single accumulation.

Grouping by a canonical key

You use grouping when many items should be bucketed by some notion of equivalence that isn't their literal value — grouping anagrams, grouping points by slope, grouping strings by shape. You compute a canonical key for each item (the thing that is identical across the group) and append the item to that key's bucket. It works because the canonical key makes "belongs to the same group" an exact dictionary match, so one pass partitions everything.

Complement / offset lookup

You use a complement lookup when, for each element, there is a specific other value whose earlier presence solves the problem — the target − x of two-sum, the run − k of subarray-sum counting, a matching bracket, a needed remainder. You store what you've seen keyed so that the needed partner is a direct lookup. It works because the relationship between the current element and its solving partner is a closed-form key, so finding the partner is O(1) rather than a search.

The template (reproduce from memory)

# Complement lookup: two-sum on an unsorted array, return indices
def two_sum(a, target):
    seen = {}                       # value -> index
    for i, x in enumerate(a):
        if target - x in seen:
            return [seen[target - x], i]
        seen[x] = i
    return []

# Frequency map: are two strings anagrams?
from collections import Counter
def is_anagram(s, t):
    return Counter(s) == Counter(t)

# Grouping by canonical key: group anagrams together
from collections import defaultdict
def group_anagrams(words):
    groups = defaultdict(list)
    for w in words:
        key = tuple(sorted(w))      # canonical form shared by anagrams
        groups[key].append(w)
    return list(groups.values())

# Seen-set: first duplicate
def first_duplicate(a):
    seen = set()
    for x in a:
        if x in seen:
            return x
        seen.add(x)
    return None

Composition — how a Hard is built from this pattern

Substring with Concatenation of All Words (Hard) — link — composes a frequency map (this lesson) with a sliding window (Lesson 3).

Show the decomposition (try it yourself first)

The ask: find every starting index in s where a concatenation of all the given equal-length words (in any order) begins. "Contains exactly these words, each the right number of times, in a contiguous stretch" smells like a window with a multiset-equality check.

Piece A — frequency map: represent the required words as a Counter. The window is valid when the words it covers match that counter exactly. Comparing multisets by key is the hashing move from this lesson.

Piece B — sliding window at word granularity: because all words share one length L, slide a window that advances L characters at a time, adding the word entering and removing the word leaving, updating a running counter incrementally — exactly the grow/shrink machine of Lesson 3, but stepping by whole words. Run it from each of the L possible offsets so every alignment is covered.

The Hard = (frequency-map equality) + (sliding window stepping by word length). Both halves are things you already own.

Reference card — Hashing Patterns

When to use it, and why

  • Seen-set. The question is pure membership — "have I encountered this exact thing before?" Add as you go, test future items against the set; O(1) presence replaces a nested earlier-scan.
  • Frequency map. The answer depends on how many times each value appears. Tally counts in one pass, then read or compare them, instead of recounting repeatedly.
  • Grouping by canonical key. Items must be bucketed by an equivalence that isn't their literal value (anagrams, slopes). Compute the shared canonical key and append; one pass partitions everything.
  • Complement / offset lookup. Each element has a specific partner value whose earlier presence solves the problem (target − x, run − k). Store seen items keyed so the partner is a direct O(1) lookup.

The one-line reason it works

A hashmap replaces an inner loop that searches or counts among already-seen elements with an O(1) recall, so an O(n²) nested scan collapses to a single O(n) pass — provided you key on the problem's true notion of sameness.

Discrimination test

Hashing gives you presence, count, and grouping in O(1) but destroys order and magnitude comparisons. If the problem needs "nearest smaller", ordering, or range queries, a hashmap alone won't do — reach for a sorted structure, a monotonic stack, or a prefix sum instead. Choosing the key is the real work; if you can't define a key that captures "sameness", hashing isn't the tool.
