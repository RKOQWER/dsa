The Knapsack Family — "take it or leave it" over a capacity

A huge slice of DP interview problems is secretly one template: you have a collection of items and a budget (capacity, target sum, amount), and at each item you choose to include it or not. 0/1 knapsack, subset-sum, partition, and coin change are all the same recurrence with small variations. Learn the one shape and you recognize the whole family instantly.

Deriving 0/1 knapsack

Items each have a weight and a value; a bag holds total weight ≤ W; maximize the value you carry. Each item is used at most once (that's the "0/1").

Derive it

Find the choice. Consider item i. Two options, and only two: put it in the bag or leave it out.

  • Leave it out: you solve the same problem on the remaining items i+1… with the same capacity.
  • Take it (only if it fits): you gain value[i], and solve the remaining items with capacity reduced by weight[i].

The transition takes the max of the two choices. So the state function is dp(i, cap) — which item we're deciding, how much capacity is left — two parameters, because both the position AND the remaining budget affect the answer.

dp(i, cap) = max(
    dp(i+1, cap),                                   # leave item i
    value[i] + dp(i+1, cap - weight[i])             # take it, if weight[i] <= cap
)

Spot the overlap: many different take/leave sequences arrive at the same (i, cap) — that's why caching on the pair (i, cap) turns the 2ⁿ decision tree into an O(n·W) table.

The key realization that defines the whole family: the capacity has to be part of the state. In 1D DP the state was a single index; here the budget you have left changes what's optimal, so it joins the index. Every member of this family is "index + remaining budget," where the budget is a weight, a target sum, or an amount of money.

The variations, each as a one-line change to the same recurrence

  • Subset-sum / Partition Equal Subset Sum: there are no values, only weights, and you ask "can I hit exactly capacity?" So the combine is or instead of max, and the base case is "capacity reached exactly → True." Partition is just subset-sum with target = totalSum / 2.
  • Unbounded knapsack / Coin Change: an item may be used any number of times. The only change is that after taking item i you may take it again — so the "take" branch recurses on dp(i, cap - weight[i]) (stay on the same item) rather than dp(i+1, …). Coin Change (min coins) uses min + 1; Coin Change 2 (count ways) uses +.
  • Count of subsets with a given sum: identical to subset-sum but combine with + to count rather than or to test existence.

The template

# 0/1 knapsack, top-down
from functools import cache
def knapsack(weight, value, W):
    n = len(weight)
    @cache
    def dp(i, cap):
        if i == n: return 0
        best = dp(i+1, cap)                              # leave
        if weight[i] <= cap:
            best = max(best, value[i] + dp(i+1, cap - weight[i]))  # take
        return best
    return dp(0, W)

# Coin Change (min coins), unbounded -> note "stay on i" in the take branch
def coinChange(coins, amount):
    @cache
    def dp(i, rem):
        if rem == 0: return 0
        if i == len(coins) or rem < 0: return float('inf')
        return min(dp(i+1, rem),                 # skip this coin type
                   1 + dp(i, rem - coins[i]))    # use it again (unbounded)
    ans = dp(0, amount)
    return ans if ans != float('inf') else -1

Composition — a Hard built from knapsack + earlier patterns

Profitable Schemes (Hard) — link. Composes the knapsack recurrence with a two-budget state and the counting-combine (+) idea from DP recognition (Lesson 26).

Show the decomposition (try it yourself first)

The problem: each "crime" uses some members and yields some profit; count the schemes (subsets of crimes) using at most n members and producing at least minProfit.

Pattern A — knapsack take/leave: for each crime, include it or not — the exact 0/1 shape. The twist is there are two budgets: members used (a normal capacity you cap at n) and profit accumulated.

Pattern B — profit as a clamped second dimension: profit is a lower bound ("at least minProfit"), not an upper bound. The trick is to clamp profit at minProfit in the state — once you've met the threshold, extra profit doesn't change which schemes count, so min(profit, minProfit) keeps the state space small. The state becomes (crime index, members left, profit-so-far clamped).

Pattern C — counting combine (Lesson 26): you want the number of schemes, so combine the take/leave branches with +, not max.

The Hard = (knapsack take/leave) + (a clamped second budget) + (count with +). The only genuinely new idea is clamping a lower-bound dimension — everything else is this lesson's template.

Reference card — Knapsack family

When, and why

Use it when you have items and a budget (weight capacity, target sum, amount of money) and at each item you choose include-or-exclude. Because many choice sequences land on the same (index, remaining-budget) state, caching that pair turns the 2ⁿ decision tree into an O(items × budget) table. The defining feature is that the remaining budget must be part of the state.

The three acts, specialized

Define the state function: dp(i, cap) = the best answer deciding items from i onward with cap budget left — the remaining budget MUST be a state parameter. Define the transition: the include-or-exclude choice, with these knobs:

  • 0/1 (each item once): take-branch recurses on i+1.
  • Unbounded (reuse allowed): take-branch recurses on i (stay).
  • Best value: combine with max/min. Count ways: combine with +. Feasible?: combine with or.

Compute the DP: memoize on (i, cap) or tabulate over items × budget; many choice sequences land on the same (i, cap), so caching turns the 2ⁿ tree into an O(items × budget) table.

Template

@cache
def dp(i, cap):
    if i == n: return 0            # or True/0 depending on variant
    best = dp(i+1, cap)            # leave
    if fits(i, cap):
        best = combine(best, gain(i) + dp(next_i, cap - cost(i)))  # take
    return best
