Deriving spiral traversal from scratch

Take the canonical case. Visit every cell of an m×n matrix in spiral order: top row left-to-right, right column top-to-bottom, bottom row right-to-left, left column bottom-to-top, then inward.

Derive it

Naive attempt: try to track a single (row, col) and a current direction, turning right whenever you'd step off the edge or onto a visited cell. This works but needs a visited-marker array and fiddly "should I turn now?" checks at every step — easy to get wrong.

Spot the waste: you are detecting the spiral's turns reactively, one cell at a time, when the structure is actually known in advance: a spiral is just four straight walks bounded by four shrinking edges. You're paying per-cell bookkeeping for a shape whose boundaries you could name up front.

The insight (= the pattern): hold four boundaries — top, bottom, left, right. Walk the top row from left to right, then drop top by one. Walk the right column, then pull right in by one. Walk the bottom row, raise bottom. Walk the left column, push left in. Repeat while top ≤ bottom and left ≤ right. No visited array and no turn-detection — each of the four walks is a plain loop between two boundaries, and shrinking the boundary after each walk encodes the spiral. Managing the four edges is the whole pattern.

The deeper principle (so it transfers)

Matrix traversal problems are usually not about a data structure but about coordinate bookkeeping: naming the right boundaries or the right coordinate transformation so the traversal becomes a set of straight, obviously-correct loops. Spiral order is four shrinking boundaries. In-place rotation is the observation that rotating 90° sends cell (r, c) to (c, n−1−r), which you can realize either by processing concentric layers and cycling four cells at a time, or by the two-step identity "transpose, then reverse each row." Setting a matrix's rows and columns to zero in place is really about choosing where to store the marks so you don't corrupt cells you haven't processed — the same index-as-hash instinct from Lesson 7, now using the first row and column as the marker storage. Once you ask "what coordinates map to what, and which boundaries bound each straight pass," the traversal writes itself.

When to use each technique, and why

Four-boundary walk (spiral and boundary traversals)

You use the four-boundary technique when a problem wants cells visited in a spiral, or wants only the boundary ring, or wants a diagonal order. You maintain the current top/bottom/left/right limits and perform one straight loop per edge, shrinking that limit afterward. It works because the traversal shape is fixed and known, so explicit boundaries replace per-cell turn detection entirely.

Layer cycling or transpose-plus-reverse (in-place rotation)

You use layer cycling when a problem asks to rotate the matrix 90° in place with no extra matrix. You either rotate four corresponding cells around each concentric square at once, or apply the transpose-then-reverse-rows identity. It works because a 90° rotation is a fixed coordinate permutation, and four cells form a closed cycle under it, so each cycle can be rotated with a single temporary.

Markers stored in the grid itself (in-place flagging)

You use in-grid markers when a problem requires modifying the matrix based on a global scan but forbids an extra m×n buffer — "set entire row and column to zero if a cell is zero" being the classic. You reserve an existing row and column (usually the first of each) to record which rows/columns must be zeroed, process the interior using those marks, then handle the reserved row and column last. It works because the first row and column are enough storage for one bit per row and per column, so you avoid allocating a parallel grid.

The template (reproduce from memory)

# Spiral order via four shrinking boundaries
def spiral_order(mat):
    if not mat: return []
    top, bottom = 0, len(mat) - 1
    left, right = 0, len(mat[0]) - 1
    out = []
    while top <= bottom and left <= right:
        for c in range(left, right + 1):      # top row L->R
            out.append(mat[top][c])
        top += 1
        for r in range(top, bottom + 1):       # right col T->B
            out.append(mat[r][right])
        right -= 1
        if top <= bottom:
            for c in range(right, left - 1, -1):   # bottom row R->L
                out.append(mat[bottom][c])
            bottom -= 1
        if left <= right:
            for r in range(bottom, top - 1, -1):   # left col B->T
                out.append(mat[r][left])
            left += 1
    return out

# Rotate 90 degrees clockwise in place: transpose, then reverse each row
def rotate(mat):
    n = len(mat)
    for i in range(n):
        for j in range(i + 1, n):
            mat[i][j], mat[j][i] = mat[j][i], mat[i][j]   # transpose
    for row in mat:
        row.reverse()                                     # reverse each row

Composition — how a harder matrix problem is built from this pattern

Game of Life (Medium, in-place variant is the hard part) — link — composes grid traversal (this lesson) with the in-place marker idea (this lesson and Lesson 7's index-as-hash instinct).

Show the decomposition (try it yourself first)

The ask: advance Conway's Game of Life one step, updating the board in place, where every cell's next state depends on its eight current neighbours. The trap: if you overwrite a cell, its neighbours later in the scan will read the new value instead of the old one.

Piece A — grid traversal: you simply visit every cell and count its live neighbours — a plain double loop over coordinates, the bread-and-butter of this lesson.

Piece B — encode two states in one cell (in-place marking): to avoid a second board, store both old and new state in each cell using extra bit values. For example let 0,1 mean "was dead/alive" and use 2 = was alive, now dead and 3 = was dead, now alive. Neighbour counting reads parity (old alive is value 1 or 2), while the new state lives in the higher bit. A final pass maps every cell to its new value. This is exactly Lesson 7's instinct — carry the auxiliary information inside the input rather than allocating a parallel grid.

The Hard = (coordinate traversal with neighbour counting) + (in-place two-state encoding). The famous "do it in place" twist is just the Lesson 7 marker trick applied to a grid.

Reference card — Matrix Traversal

When to use each, and why

  • Four-boundary walk. Spiral order, boundary ring, or ordered sweeps. Keep top/bottom/left/right, do one straight loop per edge, shrink the boundary afterward. Known shape means explicit boundaries replace per-cell turn detection.
  • Layer cycling or transpose+reverse. Rotate 90° in place. Cycle the four cells of each concentric square, or transpose then reverse each row. A rotation is a fixed coordinate permutation, and four cells form a closed cycle.
  • Markers stored in the grid. Global in-place updates with no extra buffer (set-zeroes, Game of Life). Use the first row/column, or extra bit values, to record marks, then apply them in a final pass. The grid itself carries the auxiliary bits.

The one-line reason it works

Matrix problems reduce to coordinate bookkeeping — naming the boundaries or the coordinate map that turns the traversal into straight, obviously-correct loops, and storing any marks inside the grid to stay in place.

Discrimination test

If the matrix problem is about reachability, connected regions, or shortest path through cells, it is really a graph problem (treat each cell as a node) and belongs to the graph lessons, not here. This lesson is for geometric traversal and in-place transformation, where the movement pattern is fixed and known in advance.

    top += 1

        left += 1

Complexity and classic problems
