Deriving in-place reversal from scratch

Take the canonical case. Reverse a singly linked list in place.

Derive it

Naive attempt: you'd like each node to point to its predecessor instead of its successor. But the moment you do node.next = previous, you have overwritten the link to the rest of the list — you can no longer reach the node you were about to visit next. The hazard is that a singly linked node knows only its successor, and reversing destroys exactly that knowledge.

Spot the waste / the fix: the problem isn't conceptual, it's ordering — you must save the successor before you clobber the pointer. So carry a third reference. Keep prev (the node you'll point back to), cur (the node you're reversing now), and stash nxt = cur.next before rewiring.

The insight (= the pattern): the three-pointer dance. At each step: remember nxt = cur.next; flip cur.next = prev; advance prev = cur and cur = nxt. When cur falls off the end, prev is the new head. One pass, O(n) time, O(1) space. The whole pattern is "save the next link before you overwrite it," and nearly every list-rewiring problem is a variation on that discipline.

The deeper principle (so it transfers)

Linked-list problems are almost never about clever algorithms; they are about rewiring pointers without losing the piece you still need. Two habits tame them. First, the three-pointer reversal above generalizes to reversing sublists, reordering, and swapping in pairs — always save the successor first. Second, the dummy head (a sentinel node placed before the real head) removes the special-casing that makes list code buggy: when you might delete or insert at the front, a dummy means the head is never a special position, so one uniform loop handles every case. And because a list has no indices, positional questions — the middle, the k-th from the end, cycle detection — are answered with the fast/slow two-pointer technique from Lesson 2 rather than by counting.

When to use each technique, and why

Three-pointer reversal

You use three-pointer reversal whenever a problem asks you to reverse a whole list or a contiguous sublist, or to reorder nodes by relinking rather than by copying values. You walk the nodes carrying prev, cur, and a stashed nxt, flipping each link while preserving the forward chain. It works because stashing the successor before overwriting the pointer is exactly what prevents losing the rest of the list.

Dummy head sentinel

You add a dummy head whenever nodes may be inserted or removed at the front of the list, or when you are building a new list and want a stable handle to return. You attach the dummy before the real head and operate from it, returning dummy.next at the end. It works because the dummy guarantees every real node has a predecessor, so the "what if it's the head" edge case simply disappears and one loop covers all positions.

Fast/slow for positional queries

You use fast/slow when you need a position you cannot index to — the middle node, the k-th from the end, or whether a cycle exists. You advance one pointer faster than the other so their gap or ratio pins down the target. It works for the same reason as in Lesson 2: a fixed speed relationship converts "where is the middle / the cycle" into "where does the fast pointer stop," with no length precomputation. For where a cycle begins (Linked List Cycle II), one extra fact finishes it: after the pointers meet inside the loop, moving one pointer back to the head and advancing both one step at a time makes them meet again exactly at the cycle's entry — because the distance from the head to the entry equals the distance from the meeting point to the entry.

The template (reproduce from memory)

class ListNode:
    def __init__(self, val=0, nxt=None):
        self.val = val
        self.next = nxt

# Three-pointer reversal
def reverse(head):
    prev, cur = None, head
    while cur:
        nxt = cur.next      # save before clobbering
        cur.next = prev     # flip the link
        prev, cur = cur, nxt
    return prev             # new head

# Dummy head: remove nth node from end (one pass, fast/slow)
def remove_nth_from_end(head, n):
    dummy = ListNode(0, head)
    fast = slow = dummy
    for _ in range(n):
        fast = fast.next            # open a gap of n
    while fast.next:
        fast = fast.next
        slow = slow.next            # slow stops before the target
    slow.next = slow.next.next      # unlink
    return dummy.next

# Fast/slow: middle node
def middle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
    return slow

Composition — how a Hard is built from this pattern

Reverse Nodes in k-Group (Hard) — link — composes the three-pointer reversal (this lesson), a dummy head (this lesson), and the k-th-from-position counting cousin of fast/slow (Lesson 2).

Show the decomposition (try it yourself first)

The ask: reverse the list in consecutive groups of k, leaving any final remainder of fewer than k nodes untouched. The "in groups, relink the boundaries" shape points at repeated local reversal with careful stitching.

Piece A — bounded reversal: reverse exactly k nodes using the three-pointer dance, but stop after k steps rather than at the end of the list. Pure Lesson 8.

Piece B — look-ahead count: before reversing a group, confirm at least k nodes remain by walking k steps ahead — the same "advance a pointer a fixed number of steps" idea behind fast/slow positional queries. If fewer than k remain, leave them as-is.

Piece C — dummy head stitching: a dummy before the head lets you uniformly connect the tail of each reversed group to the head of the next group, with no special case for the first group. Pure Lesson 8.

The Hard = (bounded three-pointer reversal) + (fixed-step look-ahead) + (dummy-head stitching). Each piece is something you already own; the difficulty is only in wiring them in the right order.

Reference card — Linked List Manipulation

When to use each, and why

  • Three-pointer reversal. Reverse a whole list or sublist, or reorder by relinking. Carry prev, cur, and a stashed nxt; flip each link after saving the successor. Saving the successor first is what stops you losing the rest of the list.
  • Dummy head sentinel. Inserting/removing at the front, or building a new list. Attach a dummy before the head, operate from it, return dummy.next. Every real node now has a predecessor, so the head edge case vanishes.
  • Fast/slow. Positional queries you can't index: middle, k-th from end, cycle detection. A fixed speed relationship converts the position into "where fast stops" — no length precomputation.

The one-line reason it works

List problems are pointer-rewiring under the hazard that a node knows only its successor; the fix is always to save what you still need before you overwrite it, and a sentinel removes the front-of-list special case.

Discrimination test

If a problem would be trivial on an array but is stated on a list, the challenge is almost certainly careful pointer bookkeeping, not an algorithm — reach for reversal, dummy head, and fast/slow. If you find yourself wanting random access or to "jump to index i", you may instead want to copy to an array first (allowed unless the problem forbids extra space).
