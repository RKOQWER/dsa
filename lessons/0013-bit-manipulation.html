Bit Manipulation — when the structure of the problem is the bits themselves

Bit tricks look like magic incantations to memorize. They aren't. Each one is derived from two facts: XOR cancels equal bits, and a number's bits are a set of yes/no flags. Once you see a problem through those two lenses, the "tricks" write themselves. By the end you'll derive the famous ones rather than recall them.

Warm-up — recall earlier patterns (no peeking)

1. Quickselect beats a heap for "k-th largest" only under which condition?
2. For "find the smallest value x such that a condition holds", you binary-search the answer. What must you prove about the condition?

Lens 1 — XOR cancels, so it isolates the odd one out

The single fact that powers half of all bit problems: x ^ x == 0 and x ^ 0 == x, and XOR is commutative/associative so order doesn't matter. Read that as: XOR-ing a value an even number of times erases it; an odd number of times leaves it.

Now the classic: every element appears twice except one, which appears once. Find it. Brute force: a hashmap counting occurrences, O(n) time and O(n) space. Where's the waste? You're storing full counts when you only care about parity — even vs odd.

Derive it

XOR everything together. Each value that appears twice XORs to 0 and vanishes; the lone value is XOR-ed once and survives. The answer is just reduce(xor, nums) — O(n) time, O(1) space, no hashmap. The "trick" is nothing but "XOR erases pairs," applied to the problem's exact structure.

from functools import reduce
from operator import xor
def single_number(nums):
    return reduce(xor, nums, 0)

The same lens handles "two numbers appear once, the rest twice": XOR everything to get a ^ b. Since a ≠ b, that result has at least one set bit — a bit where a and b differ. Split all numbers into two groups by that bit, and each group now has exactly one odd-one-out, reducing it to the problem you just solved. You derived the harder version from the easier one by asking "what does a set bit in a^b tell me?"

Lens 2 — a number's bits ARE a set of flags

An integer's binary form is a list of yes/no flags. Bit i set means "element i is in the set." This turns "enumerate all subsets" — which sounds like recursion — into plain counting.

Derive it

A set of n elements has 2ⁿ subsets. Each subset corresponds to an n-bit number: bit i on ⇔ element i is included. So iterating mask from 0 to 2ⁿ − 1 enumerates every subset exactly once, and mask & (1 << i) tests whether element i is in this subset. No recursion needed — the binary counter is the subset generator.

def all_subsets(elems):
    n = len(elems)
    out = []
    for mask in range(1 << n):              # 0 .. 2^n - 1
        subset = [elems[i] for i in range(n) if mask & (1 << i)]
        out.append(subset)
    return out

This bitmask-as-subset idea is the backbone of bitmask DP later in the course, where mask encodes "which items are already used." You're meeting the representation now so it's familiar then.

The handful of identities you actually reason with

Rather than memorize a wall of tricks, understand these few and derive the rest. n & (n-1) clears the lowest set bit — because subtracting 1 flips the lowest set bit and all the zeros below it, so AND-ing wipes exactly that lowest one; repeatedly doing this counts set bits, and testing n & (n-1) == 0 checks "power of two" (a power of two has exactly one set bit, so clearing it gives 0). n & (-n) isolates the lowest set bit, because two's-complement negation is "flip all bits and add 1", which leaves only the lowest set bit matching. And x ^ y marks exactly the positions where x and y differ, which is why it measures Hamming distance and isolates distinguishing bits.

Lens 3 — adding two integers without using + or -

You already know how to add on paper, column by column. Binary addition is identical, except every column holds only 0 or 1.

Step 1: the truth table for one column

absum bitcarry to next column
0000
0110
1010
1101
Compare that table to two bitwise operators: - **Sum bit** (ignoring carry) = a ^ b (XOR) - **Carry** = a & b, but it belongs to the next column to the left, so shift it: (a & b) << 1

Step 2: one round produces two pieces

partial_sum = a ^ b
carry       = (a & b) << 1
If carry == 0, stop — partial_sum is the answer. Otherwise, add partial_sum + carry using the exact same rule again. Repeat until carry becomes 0.

Step 3: walkthrough 2 + 3

2 = 0010
3 = 0011

Round 1: partial_sum = 0001 (decimal 1), carry = 0100 (decimal 4)
Round 2: partial_sum = 0101 (decimal 5), carry = 0000 (decimal 0)  → stop
Answer: 5.

Step 4: walkthrough 7 + 1 (carry ripples through several bits)

7 = 0111
1 = 0001

Round 1: partial_sum = 0110 (6),  carry = 0010 (2)
Round 2: partial_sum = 0100 (4),  carry = 0100 (4)
Round 3: partial_sum = 0000 (0),  carry = 1000 (8)
Round 4: partial_sum = 1000 (8),  carry = 0000 (0)  → stop
Answer: 8.

Step 5: why it always ends

Each round pushes the carry strictly leftward (toward higher bit positions). In a fixed-width machine, after at most 32 shifts the carry falls off the left edge and becomes 0. The loop always terminates.

Step 6: the Python problem — infinite precision

Python integers do not have a fixed width. Negative numbers are conceptually stored with infinite leading 1s (-1 is ...11111111). So the carry can become 2, 4, 8, 16... forever and never reach 0. The loop would run infinitely.

Fix: pretend we are in a 32-bit machine. After every operation, keep only the lowest 32 bits:

MASK = 0xFFFFFFFF   # 32 ones

partial_sum = (a ^ b) & MASK
carry       = ((a & b) << 1) & MASK
Now the carry cannot escape to infinity; after at most 32 shifts it vanishes.

Step 7: reading the 32-bit result as a normal Python int

After the loop, ans holds an unsigned 32-bit pattern.

  • If bit 31 is 0, the number is positive. Return it as is.
  • If bit 31 is 1, the pattern is negative in two's complement. Subtract 2^32 to get the signed Python int.
if ans >= (1 << 31):     # sign bit is set
    ans -= (1 << 32)      # subtract 2^32

Why ans -= 2^32 works (proof)

Let U be the unsigned value of an n-bit pattern and S be its signed two's-complement value. Only the leftmost bit changes weight:

Unsigned: U = 2^(n-1) + rest
Signed:   S = -2^(n-1) + rest

Subtracting: U - S = 2^(n-1) - (-2^(n-1)) = 2^n. Therefore S = U - 2^n when the sign bit is 1.

Step 8: correct code

def getSum(a: int, b: int) -> int:
    MASK = 0xFFFFFFFF
    MAX  = 0x7FFFFFFF
    while b != 0:
        carry = (a & b) << 1
        a = (a ^ b) & MASK
        b = carry & MASK
    return a if a <= MAX else a - (1 << 32)
Common mistakes
  • Forgetting to shift the carry left: carry must move to the next column: (a & b) << 1, not just a & b.
  • Stopping on b > 0 instead of b != 0: negative numbers break a greater-than check.
  • Using ~ to "fix" negatives: in Python ~x flips infinite bits and equals -x - 1. It does not convert a 32-bit unsigned pattern to a signed int.

Lens 4 — every number appears three times except one (Single Number II)

Plain XOR cancels pairs (modulo 2). Three is odd, so XOR alone leaves garbage. Instead, count each bit position separately.

Step 1: count bits per position

For each bit position i from 0 to 31, count how many numbers in the array have that bit set. Every number appearing three times contributes 3 to the count; the single number contributes 0 or 1. So count % 3 leaves exactly the single number's bit at that position.

Step 2: rebuild the answer

If count % 3 == 1, set that bit in ans. After scanning all 32 positions, ans holds the single number as an unsigned 32-bit pattern.

Step 3: convert unsigned to signed

If bit 31 (2^31) is set, the value is negative in two's complement. The signed value is unsigned - 2^32. (Same proof as Lens 3: only the sign-bit weight changes from +2^(n-1) to -2^(n-1), a gap of exactly 2^n.)

Step 4: why ~ is wrong here

In Python ~x flips every infinite bit and equals -x - 1. Applying ~ to your reconstructed answer does not give the correct negative conversion.

Correct code

def singleNumber(nums: list[int]) -> int:
    ans = 0
    for i in range(32):
        cnt = 0
        for e in nums:
            if e & (1 << i):
                cnt += 1
        if cnt % 3:
            ans |= (1 << i)
    if ans >= (1 << 31):      # sign bit set
        ans -= (1 << 32)      # convert to signed
    return ans

Lens 5 — bitwise AND of every number in [left, right]

For a result bit to be 1, every number in the range must have 1 there. If even one number has 0, that bit becomes 0 and stays dead.

Step 1: find where left and right first differ

Compare left and right from the most significant bit downward:

  • While they match, that bit survives.
  • At the first position where they differ, left has 0 and right has 1 (because left < right). The range crosses from 0 to 1, so every bit at or below that position sees at least one 0 somewhere inside the range → all those bits become 0.

Therefore the answer is just the common prefix of left and right in binary, followed by zeros for every bit from the first mismatch downward.

Step 2: walkthrough 10 to 13

10 = 1010
13 = 1101

Shift right until equal:
Shift 1: 101 vs 110  (not equal)
Shift 2: 10  vs 11   (not equal)
Shift 3: 1   vs 1    (equal)

Shift back left by 3: 1 << 3 = 1000 = 8
Brute-force check: 10 & 11 & 12 & 13 = 1010 & 1011 & 1100 & 1101 = 1000 = 8.

Step 3: algorithm

Keep shifting both left and right right until they are equal. Count the shifts. Then shift the common value back left by that count.

Correct code

def rangeBitwiseAnd(left: int, right: int) -> int:
    shift = 0
    while left != right:
        left >>= 1
        right >>= 1
        shift += 1
    return left << shift
Common mistake

When comparing the bit patterns, do not break when both bits are 0. Two zeros still match; the result bit is 0, but you must continue checking lower bits. Break only when the bits differ.

Lens 6 — count set bits for every number 0 to n (Counting Bits)

Step 1: brute force

For each i from 0 to n, count its 1-bits by checking every bit position. That is roughly O(n log n) because each number has about log(i) bits.

Step 2: look for a pattern

ibinaryans[i]
000
111
2101
3112
41001
51012
61102
71113

Notice: ans[i] equals ans[i >> 1] (the number with its last bit removed) plus the last bit itself (i & 1).

Step 3: why the recurrence holds

  • i >> 1 strips the final bit. It is smaller than i, so it is already computed.
  • i & 1 is 1 exactly when i is odd (the last bit is 1).
ans[0] = 0
ans[i] = ans[i >> 1] + (i & 1)

This is a single pass, O(n) time.

Alternative view

i & (i - 1) clears the lowest set bit, so ans[i] = ans[i & (i - 1)] + 1 also works and is also O(n).

Correct code

def countBits(n: int) -> list[int]:
    ans = [0] * (n + 1)
    for i in range(1, n + 1):
        ans[i] = ans[i >> 1] + (i & 1)
    return ans

Trap — sharpen your discrimination

Single Number II (Medium): every element appears three times except one. The instinct is "XOR everything" like Single Number I — but XOR only cancels pairs (even counts), and three is odd, so plain XOR leaves garbage. You instead track each bit's count modulo 3. Lesson: XOR is parity (mod 2); when the repetition count isn't 2, generalize to counting each bit mod k.

Sum of Two Integers (Medium): do not use + or -. Derive column addition: XOR gives the sum bit, AND-then-shift gives the carry, repeat until carry is zero. In Python, mask to 32 bits (0xFFFFFFFF) so negative numbers with infinite leading 1s do not loop forever, then subtract 2^32 if bit 31 is set to read the result as signed.

Bitwise AND of Numbers Range (Medium): the answer is the common prefix of left and right with zeros below the first mismatch. Shift both right until equal, count shifts, shift back. Do not break when both bits are zero — break only when they differ.

Counting Bits (Medium): build ans[i] = ans[i >> 1] + (i & 1) in one pass. Stripping the last bit is already computed; add whether the last bit was 1.

Composition — how a Hard is built from this pattern

Minimum Number of K Consecutive Bit Flips (Hard) — link — composes XOR parity tracking (this lesson) with a sliding-window / difference-array technique (Lessons 3 and 4) to apply range flips in O(1) each.

Show the decomposition (try it yourself first)

You may flip any length-k window of bits; find the minimum flips to make all bits 1, or −1 if impossible. Scanning left to right, each position must end up 1, and once you pass a position you can never flip it again (a flip starting earlier would extend leftward). So the decision at each index is forced — greedy — but naively applying each flip over k positions is O(n·k).

Pattern A (XOR parity): what matters at position i is only the parity of how many flips so far still cover it — flipping a bit an even number of times is a no-op, odd flips it. So you track a running parity, not the actual bit values. This is Lens 1 of this lesson: even/odd is all that counts.

Pattern B (difference array to end windows in O(1)): to know when a flip's influence ends, mark the position i + k where it stops (a difference-array / sliding-window boundary from Lessons 3–4). As you sweep, subtract expired flips from the running parity. Each flip is applied and expired in O(1), so the whole thing is O(n).

def minKBitFlips(nums, k):
    n, flips, cur = len(nums), 0, 0   # cur = running parity of active flips
    ended = [0] * (n + 1)             # difference-array marker for expiry
    for i in range(n):
        cur ^= ended[i]               # a flip that started at i-k expires here
        if (nums[i] ^ cur) == 0:      # effective bit is 0 -> must start a flip
            if i + k > n:
                return -1
            flips += 1
            cur ^= 1
            ended[i + k] ^= 1         # schedule this flip to expire at i+k
    return flips

The Hard = (XOR parity instead of real bit values) + (difference-array window boundaries) + (a greedy forced-choice sweep). Three pieces you already own. Name them and the Hard is just wiring.

Reference card — Bit Manipulation

The compressed version. Re-reading this should reload the whole pattern.

When to use it, and why

  • XOR cancellation (parity problems). When elements pair up and you need the unpaired one, or you need "which bits differ", XOR everything: equal values cancel to 0, so the odd-one-out or the differing bits survive — O(1) space, no hashmap.
  • Bits as a set of flags (subset enumeration / bitmask state). When you must enumerate all 2ⁿ subsets, or track "which of n items are used", let an integer mask be the set: bit i on ⇔ item i included. Counting mask from 0 to 2ⁿ−1 enumerates every subset once.
  • Column addition without +/-. XOR = sum without carry; AND << 1 = carry; repeat until carry is 0. Mask to 32 bits in Python; subtract 2^32 if bit 31 is set.
  • Counting each bit mod k. When every value repeats k times except one, count each bit position independently and take count % k.
  • Range AND = common prefix. Shift left and right right until equal, then shift back; everything below the first mismatch is zero.
  • DP on bits (Counting Bits). ans[i] = ans[i >> 1] + (i & 1) gives O(n) single pass.

The one-line reason it works

XOR is addition mod 2 per bit, so even occurrences vanish and only odd ones remain; and an n-bit integer is literally an n-element yes/no membership vector, so a binary counter is a subset generator.

How to derive it cold

Ask "do I only care about parity (even/odd), not exact counts?" → XOR everything. Ask "am I choosing a subset / which items are in or out?" → represent the choice as a bitmask and iterate masks. Ask "can I add without +?" → separate sum bit (XOR) from carry (AND << 1). Ask "does every number repeat k times?" → count each bit mod k. The famous tricks (n&(n-1) clears the lowest set bit, n&-n isolates it, x^y marks differences) all follow from these.

Discrimination test (when it does NOT apply)

If the repetition count isn't 2 (Single Number II's triples), plain XOR parity breaks — generalize to counting each bit mod k. If n is large (more than ~20–22), 2ⁿ bitmask enumeration is too big; the bits-as-set trick is for small n only.

Template (Python)

# XOR to isolate the unpaired value
from functools import reduce; from operator import xor
odd = reduce(xor, nums, 0)

# add two ints without + or -
MASK = 0xFFFFFFFF
while b != 0:
    carry = (a & b) << 1
    a = (a ^ b) & MASK
    b = carry & MASK
if a >= (1 << 31): a -= (1 << 32)

# count bits mod k (Single Number II)
ans = 0
for i in range(32):
    cnt = sum(1 for e in nums if e & (1 << i))
    if cnt % k: ans |= (1 << i)

# range AND = common prefix
shift = 0
while left != right:
    left >>= 1; right >>= 1; shift += 1
return left << shift

# counting bits DP
ans = [0] * (n + 1)
for i in range(1, n + 1):
    ans[i] = ans[i >> 1] + (i & 1)
