Heap Patterns — when you need the current best, repeatedly, without full sorting

A heap gives you the smallest (or largest) element in O(1) and lets you remove it or add a new element in O(log n). Reach for it whenever a problem repeatedly asks "what's the best remaining item right now?" — top-K, merge-K, streaming median, and greedy schedules that always grab the current extreme. The whole family is about avoiding a full sort you don't need.

Deriving the heap pattern via Top-K

Take K Largest Elements: return the k largest values from a list of n numbers (k ≪ n).

Derive it

Brute force: sort everything descending and take the first k → O(n log n). But you don't need the other n−k elements sorted at all; sorting them is wasted work.

Spot the waste and what you actually need. You only ever need to know, at any moment, the smallest of the k best seen so far — because the next element matters only if it beats that smallest. So maintain a collection of size k that can, cheaply: (a) tell you its minimum, and (b) remove that minimum when a bigger element arrives.

The insight (= the pattern): a min-heap of size k does exactly that. Push elements; whenever the heap exceeds size k, pop the smallest. What remains is always the k largest, and the heap's top is the k-th largest. Each push/pop is O(log k), so total O(n log k) — better than O(n log n), and it works even if the elements stream in one at a time.

import heapq
def k_largest(nums, k):
    h = []                       # min-heap of the k best so far
    for x in nums:
        heapq.heappush(h, x)
        if len(h) > k:
            heapq.heappop(h)     # drop the smallest; keep top k
    return h                     # h[0] is the k-th largest

You derived "use a heap" not by recalling it, but by asking "what is the minimum information I must maintain?" — the answer was "the current smallest of the best k," and a heap is the structure that serves that in O(log k).

The transferable shape: reach for a heap whenever you repeatedly need the current minimum or maximum of a changing set. The variations are about what you put in the heap: for merge-K sorted lists, the heap holds the current front of each list, so the global smallest is always on top; for the streaming median, you balance two heaps (a max-heap of the lower half and a min-heap of the upper half) so the median is always at one of the two tops; for greedy scheduling, the heap holds the tasks/intervals and you always pop the one with the earliest finish or highest priority. To get a max-heap in Python (which only has a min-heap), push negated values.

When to reach for a heap, and why

  • You repeatedly need the best (min or max) of a set that keeps changing (top-K, k-th largest in a stream, "schedule the next task"). A full sort is O(n log n) and becomes stale the moment the set changes; a heap exposes the current extreme in O(1) and absorbs an insertion or extreme-removal in O(log n), so repeated queries stay cheap.
  • You must merge several sorted sequences, or always consume the globally smallest among several fronts (merge-K lists, smallest range covering K lists). Putting one representative per sequence in the heap makes "which sequence has the smallest next element" an O(log k) question instead of scanning all k sequences each step.
  • You need a running statistic that depends on the extremes of two halves of the data (median of a stream). Two heaps facing each other keep the halves balanced so the middle value(s) sit at the heap tops, updatable in O(log n) per new element — impossible to keep re-sorting on a stream.

The templates

import heapq

# Merge K sorted lists: heap holds (value, list_index, node/pointer)
def merge_k(lists):
    h = [(l[0], i, 0) for i, l in enumerate(lists) if l]
    heapq.heapify(h)
    out = []
    while h:
        val, i, j = heapq.heappop(h)
        out.append(val)
        if j + 1 < len(lists[i]):
            heapq.heappush(h, (lists[i][j+1], i, j+1))
    return out

# Streaming median: max-heap (lower half, negated) + min-heap (upper half)
class MedianFinder:
    def __init__(self):
        self.lo = []   # max-heap via negation
        self.hi = []   # min-heap
    def addNum(self, x):
        heapq.heappush(self.lo, -x)
        heapq.heappush(self.hi, -heapq.heappop(self.lo))   # balance values
        if len(self.hi) > len(self.lo):                    # balance sizes
            heapq.heappush(self.lo, -heapq.heappop(self.hi))
    def findMedian(self):
        if len(self.lo) > len(self.hi): return -self.lo[0]
        return (-self.lo[0] + self.hi[0]) / 2

Composition — a Hard built from a heap + earlier patterns

Smallest Range Covering Elements from K Lists (Hard) — link. Composes a heap with the merge-K front-pointer idea and the sliding-window "shrink while valid" logic (Lesson 3).

Show the decomposition (try it yourself first)

The problem: given k sorted lists, find the smallest range [a, b] that includes at least one number from each list.

Pattern A — heap of current fronts (this lesson, merge-K flavor): keep one pointer per list and push each list's current front into a min-heap, also tracking the current maximum among the fronts. The heap's top is the current minimum front. The range right now is [min_front, current_max], and it already covers one element from every list (one per pointer).

Pattern B — advance the minimum, like a sliding window shrink (Lesson 3): to try to tighten the range, you must raise the minimum — so pop the smallest front and advance that list's pointer, pushing its next value and updating the max. This is the window-shrink move: you always discard the limiting (smallest) side to look for a tighter covering range, stopping when any list is exhausted.

The Hard = (heap to find and advance the current minimum front across k lists) + (sliding-window reasoning to shrink toward the smallest covering range). The heap is this lesson; the shrink-the-limiting-side instinct is Lesson 3.

Reference card — Heap Patterns

When, and why

Use a heap when you repeatedly need the current min/max of a changing set. It exposes the extreme in O(1) and absorbs an insert or extreme-removal in O(log n), so repeated "best right now" queries stay cheap and work on streaming data where a full sort can't. Top-K keeps a size-k heap; merge-K keeps one front per list; streaming median balances two heaps; greedy scheduling pops the current best task.

The move

Decide the single item the heap holds and whether you want min or max (negate values for a max-heap in Python). Push as data arrives; pop the extreme when the size rule or greedy rule says so. The heap top is your answer at each step.

Template

import heapq
h = []
for x in stream:
    heapq.heappush(h, key(x))
    if size_rule_violated(h): heapq.heappop(h)
# h[0] is the current extreme / answer
