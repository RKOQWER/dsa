Interval / Partition DP — the state is a range, and you choose a split point

The trickiest common DP family. Here the subproblem is a range [i, j], and the choice is "where do I split this range?" or "which element of this range do I handle last?" Matrix-chain multiplication, burst balloons, and palindrome partitioning all live here. The mental unlock is learning to iterate over an inner split point k between i and j.

1. In string DP (Lesson 30) for palindromes, what did the state (i, j) represent?
2. Lesson 26 said to fill a table in an order where dependencies are ready first. For a range state (i, j), what should that order be?

Deriving interval DP via Matrix-Chain / splitting

Classic framing: you have a range of things that must be combined, and every way of parenthesizing the combination costs differently. Minimize the total cost. (Matrix-chain multiplication is the textbook case; the same shape powers burst balloons and partitioning.)

Derive it

Find the choice: the LAST operation on the range. Over the range [i, j], something is combined last — pick the split point k where the final combination happens. That split breaks the range into [i, k] and [k+1, j], each a smaller interval of the identical problem, plus a cost for joining the two halves.

dp(i, j) = min over k in [i, j-1] of
             dp(i, k) + dp(k+1, j) + cost_of_joining(i, k, j)

Why the state function must take a range. Define dp(i, j) = the best cost over the range [i, j]. The cost of combining a sub-range depends on both its endpoints, not just its length or its start — so you cannot reduce the state to a single index. Spot the overlap: the same sub-range [i, k] appears under many different outer splits, so caching on (i, j) turns the exponential number of parenthesizations into an O(n²) number of ranges, each costing O(n) to split — O(n³) total.

The transferable shape: interval DP applies when the answer for a range is built by choosing an element or a boundary inside the range to handle last, splitting it into two independent sub-ranges. The two recurring tricks are (1) iterate the split point k across the interval, and (2) fill the table by increasing range length so both halves are ready. Burst Balloons adds one twist: instead of splitting, you choose which balloon is burst last, because that balloon's neighbors are then the fixed boundaries i-1 and j+1.

When to reach for interval DP, and why

  • The problem is about a contiguous range, and the natural decision is "where to cut it" or "which item in it to resolve last," after which the two pieces are solved independently. Because the pieces become independent once you fix the split, the range's answer is a clean combination of two smaller ranges' answers — which is exactly optimal substructure over ranges, and the sub-ranges repeat, giving overlap.
  • The cost of combining depends on the range's endpoints, not merely its length. That endpoint-dependence is the reason the state must be the full (i, j) pair rather than a single number — it's the signature that distinguishes interval DP from 1D DP.
  • "Last operation" reasoning is cleaner than "first operation." For problems like burst balloons where removing an element changes its neighbors, asking "what do I do last?" keeps the boundaries fixed and makes the sub-ranges independent; asking "what do I do first?" entangles them.

The template

# Generic interval DP: fill by increasing length, iterate split k
from functools import cache
def interval_dp(n, join_cost):
    @cache
    def dp(i, j):
        if i >= j: return 0                     # empty or single -> base
        best = float('inf')
        for k in range(i, j):                   # split point
            best = min(best, dp(i, k) + dp(k+1, j) + join_cost(i, k, j))
        return best
    return dp(0, n - 1)

# Burst Balloons flavor: choose the LAST balloon burst in (i, j)
def maxCoins(nums):
    a = [1] + nums + [1]
    @cache
    def dp(i, j):                                # open interval (i, j)
        if i + 1 == j: return 0
        best = 0
        for k in range(i + 1, j):                # k burst last
            best = max(best, a[i]*a[k]*a[j] + dp(i, k) + dp(k, j))
        return best
    return dp(0, len(a) - 1)

Composition — a Hard built from interval DP + earlier patterns

Palindrome Partitioning II (Hard) — link. Composes interval/partition DP with a precomputed string-DP palindrome table (Lesson 30) and a 1D DP over cut positions (Lesson 27).

Show the decomposition (try it yourself first)

The problem: cut a string into palindromic substrings using the minimum number of cuts.

Pattern A — string-DP palindrome table (Lesson 30): first precompute isPal[i][j] for all i ≤ j in O(n²) using the range recurrence (s[i]==s[j] and inside is palindrome). This is the interval-state idea from Lesson 30's palindrome case.

Pattern B — 1D DP over prefixes (Lesson 27): let cuts[j] = min cuts for the prefix ending at j. Then cuts[j] = min over i of (cuts[i-1] + 1) for every i where s[i..j] is a palindrome (looked up in O(1) from the table). This is a plain 1D DP whose transition is gated by the palindrome table.

The Hard = (interval/range palindrome precompute) + (1D cut DP that queries it). The partition reasoning ("where is the last cut?") is this lesson; the palindrome table is Lesson 30; the linear cut scan is Lesson 27.

Reference card — Interval / Partition DP

When, and why

Use it when the subproblem is a contiguous range and the decision is where to split it, or which item in it to resolve last, after which the two pieces are independent. Endpoint-dependent combine cost forces the state to be the full range (i, j); sub-ranges repeat across outer choices, so caching gives O(n²) states, usually O(n³) overall.

The three acts, specialized

Define the state function: dp(i, j) = the answer for the range [i, j] (the full range, because the combine cost is endpoint-dependent). Define the transition: iterate a split point k from i to j (or "k burst/resolved last") and combine dp(i, k) and dp(k±1, j) plus a join cost. Compute the DP: fill by increasing range length so both halves are ready before the range that needs them.

Template

@cache
def dp(i, j):
    if i >= j: return base
    return best over k in (i, j) of dp(i, k) + dp(k+1, j) + join(i, k, j)
