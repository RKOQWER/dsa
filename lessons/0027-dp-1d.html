1D DP — when the state is a single index

The simplest and most common DP family: the subproblem is described by one number, usually "the answer for the prefix (or suffix) ending at index i." Master this shape and you own climbing stairs, house robber, decode ways, and word break — plus the habit of reducing a linear problem to "what's the best I can do up to here."

Deriving the 1D shape

Take House Robber: houses in a line, each with money, you cannot rob two adjacent houses, maximize the take.

Derive it

Find the choice at the current step. Stand at house i. You have exactly two options: rob it, or skip it.

  • If you rob house i, you collect nums[i] but cannot touch house i-1, so the rest of your money comes from the best solution ending at i-2.
  • If you skip house i, your total is just the best solution ending at i-1.

The state function and the transition fall out directly. Define the state function dp(i) = max money robbable from houses 0..i. The transition enumerates the two choices at house i:

dp[i] = max(dp[i-1],            # skip house i
            dp[i-2] + nums[i])  # rob house i

Spot the overlap: the naive recursion recomputes dp[i-2] from both branches, exponentially. Caching it — or filling a left-to-right array — makes it O(n). And since dp[i] only looks back two steps, you don't need the whole array: two rolling variables suffice, giving O(1) space.

The transferable shape: a 1D DP exists whenever you can define the state function as "dp(i) = the best answer ending at position i" and write a transition that combines a few earlier positions. The entire family is variations on which earlier positions the transition looks back to, and how it combines them.

When to reach for 1D DP, and why

  • You are scanning a line (array or string) making a local choice at each position, and the choice's consequence reaches only a bounded number of earlier positions. Because each position depends on a few predecessors, you can compute positions left to right and each one in O(1), giving an O(n) total — far better than the exponential tree of trying every combination of choices.
  • The question asks for a best value, a count, or a yes/no over all the ways to process the line. These three map to combining predecessors with max/min, with addition, or with or — the operator is chosen by the question, as in Lesson 26.
  • You do not need to know which choices were made, only the optimal value or count. If you had to enumerate every actual configuration, that would be backtracking (Lesson 15); DP is for when only the aggregate matters and subproblems repeat.

The template

# House Robber — O(n) time, O(1) space via rolling variables
def rob(nums):
    prev2, prev1 = 0, 0          # best ending at i-2, i-1
    for x in nums:
        prev2, prev1 = prev1, max(prev1, prev2 + x)
    return prev1

# Generic 1D tabulation

    return dp[n]

Composition — a Hard built from 1D DP + earlier patterns

Maximum Sum of 3 Non-Overlapping Subarrays (Hard) — link. Composes 1D DP with prefix sum (Lesson 4) and the sliding-window fixed-size sum idea (Lesson 3).

Show the decomposition (try it yourself first)

The problem: pick three non-overlapping subarrays each of length k to maximize the total sum; return the starting indices.

Pattern A — prefix sum / fixed window (Lessons 3–4): precompute the sum of every length-k window in O(n) using a prefix-sum array, so each window sum is O(1) to look up. Call this wsum[i] = sum of the window starting at i.

Pattern B — 1D DP over "how many windows chosen so far": scan positions and keep the best single window to the left of each point, and the best pair of windows to the left, so that when you place the third window you can combine it with the best left-pair in O(1). This is a left-to-right DP where each position's answer builds on earlier positions' best-so-far — exactly the 1D shape, just carrying "best-1" and "best-2" aggregates.

The Hard = (prefix sum to get window sums fast) + (1D best-so-far DP to combine three of them). Both are tools you already have.

Reference card — 1D DP

When, and why

Use it when you scan a line making a local choice at each position whose effect reaches only a few earlier positions, and you need a best value, a count, or a yes/no over all ways to process the line. Because each position depends on a bounded number of predecessors, you compute left to right in O(n), and usually keep only the last few values for O(1) space.

The three acts, specialized

Define the state function: dp(i) = the answer for the prefix ending at i. Define the transition: write dp(i) as a combination of dp(i-1), dp(i-2), … choosing the operator from the question (max/min for best, + for count, or for possible). Compute the DP: fill left to right; since each state looks back only a bounded amount, keep the last few values for O(1) space.

Template

prev2, prev1 = base, base
for x in nums:
    cur = combine(prev1, prev2, x)
    prev2, prev1 = prev1, cur
return prev1
