Topological Sort — ordering things that depend on each other

Whenever a problem says "you must do A before B," you have a directed graph and a question about order. This lesson derives both standard solutions (Kahn's queue of zero-dependency nodes, and the DFS post-order) from the same first principle, and shows the hidden bonus: a topological sort also tells you whether the dependency graph has a cycle, which is why so many "can you finish / is it possible" problems reduce to it.

Deriving topological order from first principles

Derive it

The task: produce an order of all items such that every item appears after all of its prerequisites. (Think: courses with prerequisites, build targets, task scheduling.)

Where can you even start? The only item you can safely place first is one with no unmet prerequisites — in graph terms, a node with in-degree 0 (no incoming edges). If no such node exists, every node depends on something, which means there is a cycle and no valid order exists at all.

The insight (= Kahn's algorithm): repeatedly take any in-degree-0 node, output it, and "remove" it — which decrements the in-degree of everything it pointed to. Removing it may create new in-degree-0 nodes (their last prerequisite is now satisfied), so keep a queue of currently-free nodes. You output nodes exactly in a valid order, and each edge is processed once when its source is removed → O(V + E).

The cycle bonus: if you finish and have output fewer than V nodes, the leftover nodes form a cycle (they can never reach in-degree 0). So the same algorithm answers "is a valid ordering possible?" for free.

The DFS view (same principle, different shape): if you run DFS and record each node after all its descendants are fully explored (post-order), then a node's prerequisites finish before it does. Reverse the finishing order and you get a topological order. Detecting a back-edge to a node currently on the recursion stack reveals a cycle.

The deeper principle (so it transfers)

Topological sort is what you reach for when the problem is fundamentally about resolving things in dependency order — and the two implementations are just two ways to find "what can be done now." Kahn's peels off nodes whose dependencies are all met (think "ready queue"); DFS finishes a node only once its subtree of dependencies is done. Both are O(V + E), both detect cycles. Prefer Kahn's when you also want to process nodes level by level (for example, counting the number of dependency layers); prefer DFS when you already have a recursive structure or want the ordering as a by-product of exploration.

When to recognise a topological-sort problem

The problem gives prerequisites or an ordering constraint

If items must be done, taken, built, or compiled in an order dictated by "X requires Y first," you are looking at a directed graph and the answer is some valid linear order of that graph. The moment you can phrase a rule as a directed edge "prerequisite → dependent," topological sort is the tool.

The problem asks "is it possible / can it be finished?"

Because a valid topological order exists if and only if the directed graph has no cycle, any question of the form "can all tasks be completed?" or "is this schedule consistent?" is really a cycle-detection question, and running a topological sort answers it: you succeed if and only if you can order every node.

The problem asks you to recover a hidden ordering from constraints

Sometimes the ordering is not given directly but implied by observations (for example, deducing an alphabet order from a sorted list of words). You extract the pairwise "comes before" constraints into directed edges, then topologically sort to recover a full order consistent with all of them.

The template (reproduce from memory)

from collections import deque, defaultdict

# Kahn's algorithm (BFS style): returns a topo order, or [] if a cycle exists
def topo_sort(n, edges):          # edges: list of (prereq, dependent)
    adj = defaultdict(list)
    indeg = [0] * n
    for u, v in edges:            # u must come before v
        adj[u].append(v)
        indeg[v] += 1

    q = deque(i for i in range(n) if indeg[i] == 0)
    order = []
    while q:
        node = q.popleft()
        order.append(node)
        for nxt in adj[node]:
            indeg[nxt] -= 1       # "remove" node: one prerequisite satisfied
            if indeg[nxt] == 0:
                q.append(nxt)
    return order if len(order) == n else []   # [] means a cycle

# DFS style (post-order, reversed); detects cycle via on-stack coloring
def topo_sort_dfs(n, adj):
    WHITE, GRAY, BLACK = 0, 1, 2
    color = [WHITE] * n
    order = []
    ok = True
    def dfs(u):
        nonlocal ok
        color[u] = GRAY
        for v in adj[u]:
            if color[v] == GRAY:  ok = False      # back-edge -> cycle
            elif color[v] == WHITE: dfs(v)
        color[u] = BLACK
        order.append(u)           # post-order
    for u in range(n):
        if color[u] == WHITE:
            dfs(u)
    return order[::-1] if ok else []

Composition — how a Hard is built from this pattern

Alien Dictionary (Hard 269) composes topological sort (this lesson) with graph modeling (Lesson 20) and hashing (Lesson 5) to build the constraint edges.

Show the decomposition (try it yourself first)

The problem: you're given words sorted in an unknown alphabet's order; recover a possible letter ordering (or report it's invalid).

Piece 1 — graph modeling (Lesson 20): each distinct letter is a node. The only ordering information lives in adjacent word pairs: compare consecutive words character by character; the first position where they differ gives one directed edge "earlier letter → later letter." That single edge per adjacent pair is your entire edge set. (Watch the invalid case: if a longer word is a prefix of the earlier word, e.g. "abc" before "ab", no ordering is valid.)

Piece 2 — hashing (Lesson 5): store the node set and adjacency in dicts/sets so you don't duplicate edges and can track in-degrees per letter.

Piece 3 — topological sort (this lesson): run Kahn's over the letters. If you emit every letter, that's a valid alphabet; if a cycle blocks you, the input is inconsistent and you return "".

from collections import defaultdict, deque

def alienOrder(words):
    adj = defaultdict(set)
    indeg = {c: 0 for w in words for c in w}      # Piece 2: hashing nodes
    for a, b in zip(words, words[1:]):            # Piece 1: build edges
        for x, y in zip(a, b):
            if x != y:
                if y not in adj[x]:
                    adj[x].add(y); indeg[y] += 1
                break
        else:
            if len(a) > len(b):                   # invalid prefix case
                return ""
    q = deque([c for c in indeg if indeg[c] == 0])
    out = []
    while q:                                       # Piece 3: topo sort
        c = q.popleft(); out.append(c)
        for nxt in adj[c]:
            indeg[nxt] -= 1
            if indeg[nxt] == 0: q.append(nxt)
    return "".join(out) if len(out) == len(indeg) else ""

The Hard = (model letters-as-nodes, adjacent-word diffs as edges) + (hashing to dedupe edges and track in-degree) + (topological sort to linearise, with cycle = invalid).

Reference card — Topological Sort

The compressed version.

When and why

Use it when the problem is about ordering items under "X before Y" dependencies, or asks "is a consistent schedule possible?" A valid order exists iff the directed graph is acyclic, so topo sort doubles as cycle detection.

Two implementations, same principle

  • Kahn's (queue of in-degree-0 nodes). Repeatedly output a node with no unmet prerequisites and decrement its neighbours' in-degrees. If you output fewer than V nodes, there's a cycle. Natural when you also want to count dependency layers.
  • DFS post-order. Record a node after its whole subtree finishes, then reverse. A back-edge to a node still on the recursion stack signals a cycle. Natural when a recursive structure already exists.

Both are O(V + E).

Template (Kahn's)

indeg[v] += 1 for each edge u->v; adj[u].append(v)
q = deque(nodes with indeg 0)
while q:
    u = q.popleft(); order.append(u)
    for v in adj[u]:
        indeg[v] -= 1
        if indeg[v] == 0: q.append(v)
# cycle iff len(order) < V
